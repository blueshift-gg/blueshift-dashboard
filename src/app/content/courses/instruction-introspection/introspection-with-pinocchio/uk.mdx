# Інструкція Самоаналізу з Pinocchio

Pinocchio використовує інші типи, ніж крейт `solana_program`. Це означало, що нам довелося створити новий SDK, оптимізований для Pinocchio.

Дякуючи [Orion](https://x.com/BasedOrion_), Ми створили набір помічників, які поважали "оригінальну" реалізацію, але зробили системну змінну `Instruction` — одну з найдорожчих системних змінних у використанні — однією з найефективніших.

З цієї причини ми можемо використовувати *Інструкцію самоспостереження* в Pinocchio без встановлення будь-яких зовнішніх ящиків та можемо отримати доступ до всієї необхідної інформації, імпортувавши ці функції:

```rust
use pinocchio::sysvars::instructions::{
    load_current_index_checked, 
    load_instruction_at_checked
}; 
```

<ArticleSection name="Як використовувати інтроспекцію" id="how-to-use-introspection" level="h2" />

Як згадувалося раніше, інтроспекція інструкцій просто десеріалізує дані з облікового запису sysvar `Instruction`, щоб надати всі необхідні дані про наші інструкції.

Ми починаємо з перевірки поточного індексу. Ми можемо зробити це за допомогою функції `load_current_index_checked`, ось так:

```rust
let index = load_current_index_checked(&self.accounts.sysvar_instructions)?;
```

Після цього ми можемо перевірити інструкцію за відносною індексною лінією, використовуючи `load_instruction_at_checked`. Цього разу ми перевіримо інструкцію, що йде одразу після тієї, що виконує інтроспекцію, ось так:

```rust
// Ми завантажуємо наступну інструкцію, яку ми хочемо перевірити на правильність введення.
let instruction = load_instruction_at_checked(index as usize + 1, &self.accounts.sysvar_instructions)?;
```
Перш ніж перейти до наступного кроку, нам слід запитати себе, яка інформація є важливою для запобігання зловмисній атаці.

Зазвичай ми починаємо з перевірки, чи використовується програма, яку ми очікуємо. У цьому прикладі ми аналізуємо іншу інструкцію із системної програми, тому ми можемо зробити це так:

```rust
if instruction.get_program_id() != &pinocchio_system::ID {
    return Err(ProgramError::InvalidInstructionData);
}
```

Далі ми перевіряємо, чи інструкція відповідає очікуваним значенням. Для цього ми порівнюємо дискримінатор та дані інструкції з очікуваними значеннями. Ми починаємо зі створення змінної `instruction_data` та перевірки з нею, ось так:

```rust
let mut instruction_data = [0u8; 12];
instruction_data[0..4].copy_from_slice(&2u32.to_le_bytes());
instruction_data[4..12].copy_from_slice(&100_000_000u64.to_le_bytes());

if instruction.get_instruction_data() != instruction_data {
    return Err(ProgramError::InvalidInstructionData);
}
```
Потім ми можемо виконати більше специфічних для програми перевірок на основі логіки інструкції, яку ми перевіряємо.

Ми також можемо перевірити облікові записи, присутні в інтроспективній інструкції. Цей крок вимагає від нас знання точної структури структури облікового запису, оскільки ми будемо запитувати дані або публічний ключ облікового запису за певним індексом, ось так:

```rust
if instruction.get_account_meta_at(0)?.key() != self.accounts.from.key() {
    return Err(ProgramError::InvalidAccountData);
}
```
