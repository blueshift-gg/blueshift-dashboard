# 중복 mutable account

중복 mutable account 공격은 동일한 유형의 여러 mutable account를 허용하는 프로그램을 악용하여, 동일한 account를 두 번 전달함으로써 프로그램이 자신의 변경 사항을 인지하지 못한 채 덮어쓰도록 만듭니다. 이는 단일 instruction 내에서 race condition을 생성하여, 나중에 발생한 mutation이 이전에 발생한 mutation을 조용히 무효화할 수 있습니다.

이 취약점은 주로 프로그램 소유 account의 데이터를 수정하는 instruction에 영향을 미치며, lamport transfer와 같은 시스템 operation에는 해당하지 않습니다. 이 공격이 성공하는 이유는 Solana 런타임이 동일한 account가 여러 번 다른 파라미터로 전달되는 것을 방지하지 않기 때문이며, 중복을 감지하고 처리하는 것은 프로그램의 책임입니다.

위험은 instruction 실행의 순차적 특성에 있습니다. 동일한 account가 두 번 전달될 때, 프로그램은 첫 번째 mutation을 수행한 다음, 두 번째 mutation으로 즉시 덮어씁니다. 이로 인해 account는 사용자 의도나 프로그램 논리를 반영하지 않는 예기치 않은 상태로 남게 됩니다.

두 개의 프로그램 account에서 소유권 필드를 업데이트하는 다음 취약한 instruction을 고려해보십시오.

```rust
#[program]
pub mod unsafe_update_account{
    use super::*;
    
    //..

    pub fn update_account(ctx: Context<UpdateAccount>, pubkey_a: Pubkey, pubkey_b: Pubkey) -> Result<()> {
        ctx.accounts.program_account_1.owner = pubkey_a;
        ctx.accounts.program_account_2.owner = pubkey_b;
        
        Ok(())
    }

    //..

}

#[derive(Accounts)]
pub struct UpdateAccount<'info> {
   #[account(mut)]
    pub program_account_1: Account<'info, ProgramAccount>,
    #[account(mut)]
    pub program_account_2: Account<'info, ProgramAccount>,
}

#[account]
pub struct ProgramAccount {
    owner: Pubkey,
}
```

이 코드에는 치명적인 결함이 있습니다. 바로 `program_account_1`과 `program_account_2`가 서로 다른 account인지 전혀 확인하지 않는다는 점입니다.

공격자는 두 파라미터에 동일한 account를 전달함으로써 이를 악용할 수 있습니다. 다음은 발생하는 상황입니다.
- 프로그램은 `program_account_1.owner = pubkey_a`로 설정합니다.
- 두 파라미터가 동일한 account를 참조하므로, 프로그램은 이를 즉시 `program_account_2.owner = pubkey_b`로 덮어씁니다.

최종 결과: account의 owner는 `pubkey_b`로 설정되며, `pubkey_a`는 완전히 무시됩니다.

이는 무해해 보일 수 있지만, 그 영향을 고려해보십시오. 특정 소유권 할당으로 두 개의 다른 account를 업데이트하려던 사용자는 단 하나의 account만 수정되었으며, 의도했던 방식이 아니라는 것을 알게 됩니다. 복잡한 프로토콜에서는 이는 일관성 없는 상태, 실패한 다단계 operation, 심지어 금전적 손실로 이어질 수 있습니다.

해결책은 간단합니다. 진행하기 전에 account가 고유한지 확인하기만 하면 됩니다.

```rust
pub fn update_account(ctx: Context<UpdateAccount>, pubkey_a: Pubkey, pubkey_b: Pubkey) -> Result<()> {
    if ctx.accounts.program_account_1.key() == ctx.accounts.program_account_2.key() {
        return Err(ProgramError::InvalidArgument)
    }

    ctx.accounts.program_account_1.owner = pubkey_a;
    ctx.accounts.program_account_2.owner = pubkey_b;

    Ok(())
}
```
