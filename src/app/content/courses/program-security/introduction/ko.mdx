# Program Security

![Program Security](/graphics/course-banners/program-security.png)

> [Unboxed Software](https://x.com/unboxedsoftware)가 이 코스의 초기 콘텐츠를 선도하고 구축하는 데 크게 기여했습니다!

매일 수백만 달러가 Solana 프로그램들을 통해 전광석화처럼 빠르게 흘러갑니다. 이렇게 이해관계가 높고 고성능 환경에서 취약한 코드 한 줄은 프로토콜을 몇 초 만에 고갈시킬 수 있는 반면, 잘 보호된 프로그램은 초당 수천 개의 transaction을 아무런 문제 없이 처리할 수 있습니다.

Solana의 혁신적인 병렬 처리(parallel processing) 아키텍처는 다른 블록체인보다 빠를 뿐만 아니라, 근본적으로 다릅니다.

Ethereum 개발자들이 gas optimization과 sequential execution에 대해 고민하는 동안, Solana 개발자들은 account가 storage를 대체하고, 프로그램이 stateless하며, transaction들이 병렬 실행(parallel execution) 레인에서 서로 경쟁하는 완전히 새로운 위협 환경을 숙달해야 합니다.

Solana 블록체인 개발에는 고유한 많은 보안 exploit이 존재합니다. 이 과정에서는 [Coral의 Sealevel Attack repository](https://github.com/coral-xyz/sealevel-attacks)를 기반으로 모델링된 모든 Sealevel Attack을 실제 사례와 실용적인 완화 전략을 통합하여 학습하게 됩니다.

프로그램을 Mainnet에 배포하기 전에 보안 기본 사항에 대한 최소한의 이해가 있어야 합니다.

> 동일한 exploit은 Native 및 Anchor 개발 모두에 "유효"합니다.

Solana 개발에서 가장 중요한 보안 고려 사항은 플랫폼의 account 소유권 모델과 프로그램이 account와 상호 작용하는 방식에서 비롯됩니다.

프로그램은 account 소유권을 신중하게 검증하고, 적절한 접근 제어(access control)를 구현하며, 교차 프로그램 호출(cross-program invocations, CPIs)의 복잡성을 처리해야 합니다.

프로그램의 stateless 특성은 악의적인 account 조작에 대한 내장된 보호 장치가 없으므로 모든 유효성 검사 로직(validation logic)이 명시적으로 구현되어야 함을 의미합니다.

또한 Solana 프로그램의 일반적인 취약점 패턴에는 누락된 소유권 확인(ownership check), 불충분한 서명자 검증(signer verification), 산술 오버플로우/언더플로우(arithmetic overflow/underflow), 그리고 account 초기화 및 종료의 부적절한 처리가 포함됩니다.

> Anchor는 개발자들이 특정 타입을 사용하거나 프로그램에 대한 의도적인 선택을 하도록 강제함으로써 Solana 프로그램을 더욱 안전하게 만들겠다는 아이디어로 개발되었습니다.

각 보안 취약점이 언뜻 보기에 "단순"해 보일지라도, 각 시나리오에는 상당한 깊이가 논의될 수 있습니다. 이 강의는 이론보다는 더 많은 실용적인 코드 예제를 포함하여, 논의된 보안 위험에 대해 확실하고 실질적인 이해를 얻을 수 있도록 보장합니다.

Solana 보안 지식을 향상시킬 준비가 되셨나요? 함께 더 안전한 프로그램을 구축해 봅시다.
