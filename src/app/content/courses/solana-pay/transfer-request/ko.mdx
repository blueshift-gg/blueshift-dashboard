# 전송 요청

전송 요청은 Solana Pay의 가장 간단한 결제 방식으로, 서버 상호작용 없이 간단한 SOL 또는 SPL 토큰 전송을 위해 설계되었습니다. 사용자가 QR 코드를 스캔하거나 전송 요청 링크를 클릭하면, 월렛은 트랜잭션을 즉시 구성하고 실행하는 데 필요한 모든 것을 갖추게 됩니다.

전송 요청의 장점은 그 단순성에 있습니다. 모든 결제 정보가 URL에 직접 인코딩되어 있어, 완전히 독립적이며 즉시 실행 가능합니다.

<ArticleSection name="URL Structure and Parameters" id="url-structure" level="h2" />

전송 요청 URL은 모든 Solana 월렛이 해석할 수 있는 표준화된 형식을 따릅니다:

```
solana:<recipient>?<optional-query-params>
```

**필수 매개변수:**
- `recipient`: 대상 월렛을 나타내는 base58 인코딩된 public key입니다. 이것은 유일한 필수 필드이며, 중개자 없이 고객에서 판매자에게 직접 결제가 이루어지도록 보장합니다.

**선택적 매개변수:**
- **`amount`**: 정확한 전송 금액을 십진수 값으로 지정합니다. 이 값이 없으면 월렛은 사용자에게 금액을 수동으로 입력하라고 요청합니다. 이는 기부 또는 유연한 결제 시나리오에 적합합니다.
- **`spl-token`**: SPL 토큰 전송을 위한 민트 주소입니다. SOL 전송을 USDC 결제부터 맞춤형 로열티 토큰까지 모든 토큰 전송으로 변환합니다.
- **`reference`**: 온체인에서 결제를 추적하기 위한 고유 식별자입니다. 판매자는 트랜잭션 서명을 제어하지 않으므로, 참조는 결제 조정 및 고객 지원을 위한 검색 가능한 식별자 역할을 합니다.
- **`label` and `message`**: 결제 컨텍스트를 설명하는 사용자 대면 문자열입니다. label은 일반적으로 판매자를 식별하고, message는 특정 구매를 설명합니다.
- **`memo`**: Solana의 memo 프로그램을 사용하여 온체인 기록을 생성합니다. 규정 준수, 회계 또는 영구적인 트랜잭션 컨텍스트 제공에 유용합니다.

### 예시

다음은 실제 매개변수 사용법을 보여주는 1 SOL에 대한 전송 요청입니다:

```
solana:22222222222222222222222222222222222222222222?amount=1&label=Blueshift%20Subscription&message=1%20Month&memo=Order12345&reference=abc123def456
```

스테이블코인을 받는 기업의 경우, 여기 USDC 전송 요청이 있습니다:

```
solana:22222222222222222222222222222222222222222222?amount=200&spl-token=EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v&label=Blueshift%20Subscription&message=1%20Month&memo=Order12345&reference=abc123def456
```

<ArticleSection name="When to Use Transfer Requests" id="when-to-use" level="h2" />

전송 요청은 결제 세부 정보가 미리 결정되어 있고 변경되지 않는 시나리오에서 특히 유용합니다:

**완벽한 사용 사례:**
- 고정 가격 책정 시 **이커머스 결제**
- 사용자가 금액을 선택하는 **기부 캠페인**
- 알려진 금액으로 **구독 결제**
- 오프라인 거래를 위한 **POS 시스템**
- 특정 금액으로 **송장 결제**

**주요 장점:**
- **비상호작용적 특성:** 일단 생성되면, 이 URL들은 서버와 독립적으로 작동합니다. 네트워크 연결이 불안정하거나 인프라 종속성을 최소화하려는 상황에 적합합니다.
- **실행 보장:** 결제 매개변수가 URL에 고정되어 있어, 동적 가격 변동 없이 고객이 예상한 금액을 정확히 지불하도록 보장합니다.
- **오프라인 기능:** URL은 POS 단말기와 같은 기기에서 로컬로 생성될 수 있으며, 백엔드 시스템이 일시적으로 사용 불가능한 경우에도 결제를 가능하게 합니다.
- **서버 부하 감소:** 결제 처리 중에 API 호출이 필요 없으므로, 대량 처리 시나리오에 매우 확장성이 좋습니다.
- **보편적 호환성:** 모든 Solana 월렛이 월렛별 통합이 필요 없이 이 요청을 처리할 수 있습니다.

보장된 결제 금액이 필요하거나, 서버 종속성을 줄이고 싶거나, 모든 네트워크 조건에서 안정적으로 작동하는 결제 방법이 필요한 경우 전송 요청을 고려하십시오.
