# Weighted Pools

All AMMs that we talked about till now, aim to have their internal liqudity 50/50: for a SOL-USDC pair for example, you aim to have half your value in SOL, and the other half in USDC. 

This works perfectly for most usecases, but fall short when for example you're bullish on SOL and want 80% exposure or if you want to create a single pool holding SOL, BONK, JTO, and JUP, like an on-chain index fund that rebalances itself.

Weighted pools generalize the AMM formula to support arbitrary weights and multiple assets.

<ArticleSection name="Beyond the 50/50 split" id="beyond-5050" level="h2" />

### The Limitation of Constant Product

In `x * y = k` pools:
- Token A value = Token B value (always)
- Two tokens maximum per pool
- LPs must deposit equal values of both

This works for normal trading pairs but falls short in these scenarios:

**Index exposure**: You want 50% SOL, 30% JTO, 20% BONK exposure. With constant product, you'd need multiple positions across multiple pools, manually rebalancing.

**Treasury management**: Your protocol holds 80% governance token, 20% USDC. You want to provide liquidity without selling most of your tokens.

**Token launches**: You're launching a token and want to start at 90% your token / 10% USDC, gradually shifting to 50/50.

### The Weighted pool insight

Generalize the invariant to support:
1. Arbitrary weights (not just 50/50)
2. Multiple tokens (not just pairs)
3. Self-balancing portfolios

<ArticleSection name="The Weighted Math" id="weighted-math" level="h2" />

### The Invariant

Balancer uses the weighted geometric mean:

```
V = Π(B_i ^ W_i)

Where:
- V = invariant value
- B_i = balance of token i
- W_i = weight of token i
- Σ(W_i) = 1 (weights sum to 100%)
```

For a two-token 50/50 pool:

```
V = B_0^0.5 * B_1^0.5 = sqrt(B_0 * B_1)

This is exactly sqrt(x*y) = sqrt(k)
```

So the constant product is just a special case of weighted pools!

### Spot Price Formula

The spot price between any two tokens:

```
SP_i/j = (B_j / W_j) / (B_i / W_i)

Where:
- SP_i/j = spot price of token i in terms of token j
- B = balance
- W = weight
```

For 80/20 SOL/USDC with 2000 SOL and 50,000 USDC:

```
SP_SOL/USDC = (50000 / 0.2) / (2000 / 0.8)
           = 250000 / 2500
           = 100 USDC per SOL
```

### Swap Output Formula

For an exact input swap:

```
A_o = B_o * (1 - (B_i / (B_i + A_i))^(W_i/W_o))

Where:
- A_o = amount out
- A_i = amount in
- B_o = balance out (before swap)
- B_i = balance in (before swap)
- W_i = weight in
- W_o = weight out
```

The exponent `W_i/W_o` is key. In constant product pools, this equals 1 but in weighted pools, it changes the price curve.

<ArticleSection name="Price Curves by Weight" id="price-curves" level="h2" />

### How Weights Affect Price Impact

Different weights create different curves:

**50/50 (standard AMM)**:
```
Selling 10% of token A balance:
→ ~9% price impact
```

**80/20 (heavy token A)**:
```
Selling 10% of token A balance:
→ ~2.5% price impact (on A)
→ Token A is "heavier", harder to move

Selling 10% of token B balance:
→ ~30% price impact (on B)
→ Token B is "lighter", moves easily
```

### Why This Matters

For an 80/20 pool where you want to maintain exposure:
- Large sells of the 80% token cause less slippage
- The pool naturally resists rebalancing away from target weights
- Ideal for treasuries that want to maintain token allocation

### Impermanent Loss by Weight

IL is reduced for the heavier token:

```
50/50 pool, 2x price change: 5.7% IL
80/20 pool, 2x price change of 80% token: ~1.0% IL
80/20 pool, 2x price change of 20% token: ~16% IL
```

The heavy token has natural protection while the light token has amplified exposure.

<ArticleSection name="Multi-Token Pools" id="multi-token" level="h2" />

As we said before, weighted pools can support different tokens.

All tokens are tradeable against each other and the LP token represents exposure to all of them; this means that if you wanted to swap two assets that required a multi-hop, you could actually directly route them through the pool.

### How Multi-Token Swaps Actually Work

In a constant product world, if you want to swap BONK for PYTH, you need to find a routing path:

```
BONK → SOL → PYTH

Step 1: BONK/SOL pool
  - You sell 1M BONK
  - Pay 0.3% fee
  - Get 10 SOL
  - Price impact: 0.5%

Step 2: SOL/PYTH pool
  - You sell 10 SOL  
  - Pay 0.3% fee
  - Get 25 PYTH
  - Price impact: 0.3%

Total fees: 0.6%
Total slippage: ~0.8%
Accounts needed: 4+ (two pools, token accounts)
```

In a weighted pool with all these tokens:

```
BONK → PYTH (direct)

Single swap through the multiple token pool:
  - You sell 1M BONK
  - Pay 0.3% fee once
  - Get 25.5 PYTH
  - Price impact: 0.4%

Total fees: 0.3%
Total slippage: ~0.4%
Accounts needed: 2 (one pool, your token accounts)
```

You got 2% more PYTH because you avoided the second fee and the compounded slippage.

### What Multi-Token Pools Don't Do

A common misconception: "all $10M of TVL is available for any swap." That's not true.

```
8-token pool: $10M total
  - 30% SOL ($3M)
  - 15% JUP ($1.5M)
  - 10% BONK ($1M)
  - ...

To swap JUP → BONK:
  You're still limited by the JUP and BONK reserves
  The SOL in the pool doesn't help this specific swap
```

> The depth for JUP-BONK is determined by those tokens' reserves, not the total pool TVL.

### What Multi-Token Pools Actually Give You

The real advantages:

**1. Routing efficiency**: One hop instead of two means one fee instead of two, and no compounded slippage.

**2. LP convenience**: Instead of managing 28 separate pair positions, you have one position that earns fees from all 28 pairs.

**3. Capital efficiency for LPs**: Your $10K deposit earns fees whenever *any* pair trades, not just one specific pair.

**4. Rebalancing**: The pool automatically maintains target weights so you get paid to rebalance instead of paying for it.

<ArticleSection name="Liquidity Bootstrapping Pools (LBPs)" id="lbps" level="h2" />

But the weighted pool formula doesn't just solve for multi-asset tokens. 

It can help solve fair token launches through LBPs (Liquidity Boostrapping Pools)

### The Token Launch Problem

Traditional token launches suffer from:
- Bots front-running public sales and accumulating supply to dump on retail
- Initial price discovery chaos: too low and everyone will buy it up in seconds, too high and nobody is going to buy.

### How LBPs Work

An LBP is a weighted pool where the weights change over time.

Remember the spot price formula:

```
Price = (B_USDC / W_USDC) / (B_TOKEN / W_TOKEN)
```

If you change the weights, you change the price, even if the liquidity remains the same.

For example: if we create a token where the initial pool is made by 10M TOKEN and 100K USDC with a starting weights of 96% TOKEN / 4% USDC and ending weights of 50% TOKEN / 50% USDC

At the start the price would be: 

```
Price = (100,000 / 0.04) / (10,000,000 / 0.96)
      = 2,500,000 / 10,416,667
      = $0.24 per TOKEN
```

And without any swaps (so without anybody buying and changing the internal liqudity) we would have:

```
Price = (100,000 / 0.27) / (10,000,000 / 0.73)
      = 370,370 / 13,698,630
      = $0.027 per TOKEN
```

This means that the price dropped 89% with zero selling, just from the weight change.

If in the meantime people have been buying the calculations are completely different:

```
Pool now: 8M TOKEN + 300K USDC (people bought 2M tokens)
Price = (300,000 / 0.27) / (8,000,000 / 0.73)
      = 1,111,111 / 10,958,904
      = $0.10 per TOKEN
```

Buying pressure pushes price up, but the weight shift pushes it down. This creates the perfect mechanism to find equilibrium and push for fair price-discovery.

### Why This Make Launches More Fair

In a normal launch, being first is where the frontrunners make all the money. In an LBP, being first give you the worst pricing.

This means that bots can't profit by being fast. There's no advantage to front-running when the price only goes down over time.

This works because LBPs are essentially Dutch auctions encoded in AMM math:

1. Start at an absurdly high price (no one should buy at hour 0)
2. Price falls continuously as weights shift
3. Buyers enter when price reaches their valuation
4. If too many buy, price stabilizes or rises slightly
5. If no one buys, price keeps falling until it's attractive

The market discovers the fair price organically without risking the team to set it arbitrarily.

### What the Team Gets

As people buy TOKEN, USDC flows into the pool. When the sale ends:

```
Starting: 10M TOKEN + 100K USDC
Ending:   6M TOKEN + 800K USDC

Team received: 700K USDC for 4M tokens = $0.175 average price
Remaining: 6M TOKEN still in pool, tradeable at market price
```

The team doesn't dump tokens. They gradually sell through the weight mechanism, with price discovery built in.

<ArticleSection name="Key Takeaways" id="takeaways" level="h2" />

1. **Weighted pools** generalize constant product to arbitrary token weights
2. **The invariant** is the weighted geometric mean: `V = Π(B_i ^ W_i)`
3. **Multi-token pools** support up to 8 tokens trading against each other
4. **Heavier tokens** have lower slippage and IL protection
5. **LBPs** use changing weights for fair token launches
6. **Self-rebalancing**: Pools maintain target allocation automatically
7. **Best for portfolios**, treasuries, and token launches, not raw trading efficiency

Weighted pools solve problems that other AMM designs can't. They're not the most capital efficient for trading, but they enable use cases like on-chain index funds and treasury management that don't exist elsewhere.
