# Anchor 101

![Вступ до Anchor](/graphics/course-banners/introduction-to-anchor.png)

<ArticleSection name="Що таке Anchor" id="what-is-anchor" level="h2" />

Anchor — це провідний фреймворк для розробки смарт-контрактів Solana, що пропонує повний робочий процес для написання, тестування, розгортання та взаємодії з ончейн-програмами.

### Ключові переваги

- **Зменшення шаблонів**: Anchor абстрагує повторювану роботу з управління обліковими записами, серіалізації інструкцій та обробки помилок, щоб ви могли зосередитися лише на основній бізнес-логіці.
- **Вбудована безпека**: Ретельні перевірки, такі як перевірка власності облікового запису та валідація даних, впроваджуються одразу після встановлення, усуваючи багато поширених вразливостей до їх виявлення.

### Anchor Макроси

- `declare_id!()`: Оголошує, за якою адресою в мережі знаходиться програма.
- `#[program]`: Позначає модуль, який містить кожну точку входу інструкції та функцію бізнес-логіки.
- `#[derive(Accounts)]`: Перелічує облікові записи, які вимагає інструкція, та автоматично застосовує їхні обмеження.
- `#[error_code]`: Визначає власні, зрозумілі для людини типи помилок, які роблять налагодження зрозумілішим та швидшим.

Разом ці декларативні макроси абстрагують низькорівневе керування байтами, дозволяючи вам створювати безпечні програми Solana виробничого класу з набагато меншими зусиллями.

### Структура Програми

Почнемо з базової версії програми, щоб детально пояснити, що насправді робить кожен макрос:

```rust
declare_id!("22222222222222222222222222222222222222222222");

#[program]
pub mod blueshift_anchor_vault {
    use super::*;

    pub fn deposit(ctx: Context<VaultAction>, amount: u64) -> Result<()> {
        // ...
        Ok(())
    }

    pub fn withdraw(ctx: Context<VaultAction>) -> Result<()> {
        // ...
        Ok(())
    }
}

#[derive(Accounts)]
pub struct VaultAction<'info> {
    // ...
}

#[error_code]
pub enum VaultError {
    // ...
}
```

Це перетворить його на цілеспрямовані модулі, замість того, щоб все втискати в `lib.rs` для більш структурованих програм. Дерево папок програми виглядатиме приблизно так:

```
src
├── instructions
│       ├── instruction1.rs
│       ├── mod.rs
│       ├── instruction2.rs
│       └── instruction3.rs
├── errors.rs
├── lib.rs
└── state.rs
```

#### `declare_id!()`
Макрос `declare_id!()` призначає вашій програмі її адресу в мережі; унікальний відкритий ключ, отриманий з пари ключів у папці `target` проекту. Ця пара ключів підписує та розгортає скомпільований бінарний файл `.so`, що містить всю логіку та дані програми.

**Примітка:** Ми використовуємо заповнювач `222222...` у прикладах Blueshift через наш внутрішній набір тестів. У продакшені Anchor генеруватиме для вас новий ідентифікатор програми, коли ви запускатимете стандартні команди збірки та розгортання.

#### `#[program]` & `#[derive(Accounts)]`
Кожна інструкція має власну структуру **Context**, яка містить список усіх облікових записів та, за бажанням, будь-які дані, необхідні для інструкції.

У цьому прикладі і `deposit`, і `withdraw` використовують одні й ті ж облікові записи; з цієї причини ми створимо єдину структуру облікового запису під назвою `VaultAction`, щоб зробити все ефективнішим та простішим.

#### Більш вутальний розгляд `#[derive(Accounts)]` макросу

```rust
#[derive(Accounts)]
pub struct VaultAction<'info> {
  #[account(mut)]
  pub signer: Signer<'info>,

  #[account(
    mut,
    seeds = [b"vault", signer.key().as_ref()],
    bump,
  )]
  pub vault: SystemAccount<'info>,

  pub system_program: Program<'info, System>,
}
```
Як видно з фрагмента коду, макрос `#[derive(Accounts)]` виконує три критичні обов'язки:
- Оголошує всі облікові записи, необхідні для певної інструкції.
- Автоматично застосовує перевірки обмежень, блокуючи багато помилок та потенційних експлойтів під час виконання.
- Генерує допоміжні методи, які дозволяють безпечно отримувати доступ до облікових записів та змінювати їх.

Це досягається за допомогою комбінації типів облікових записів та вбудованих атрибутів.

**Типи облікових записів у нашому прикладі**
- `Signer<'info>`: Перевіряє, чи обліковий запис підписав транзакцію; важливо для безпеки та для CPI, які вимагають підпису.
- `SystemAccount<'info>`: Підтверджує право власності на обліковий запис системною програмою.
- `Program<'info, System>`: Забезпечує, щоб обліковий запис був виконуваним та відповідав ідентифікатору системної програми, що дозволяє використовувати такі CPI, як створення облікового запису або перенесення даних за допомогою Lamport.

**Вбудовані атрибути, з якими ви зіткнетеся**
- `mut`: Позначає обліковий запис як змінюваний; обов'язковий для будь-яких змін балансу або даних Lamport.
- `seeds & bump`: Перевіряє, чи є обліковий запис адресою, отриманою з програми (PDA), згенерованою з наданих seed-значень плюс байт bump.

**Примітка** PDA важливі, оскільки:
- Коли використовуються програмою, якій вони належать, PDA можуть підписувати CPI від імені програми.
- Вони надають вам детерміновані, перевірені адреси для збереження стану програми.

#### `#[error_code]`

Макрос `#[error_code]` дозволяє вам визначати чіткі, користувацькі помилки всередині програми.

```rust
#[error_code]
pub enum VaultError {
    #[msg("Vault already exists")]
    VaultAlreadyExists,
    #[msg("Invalid amount")]
    InvalidAmount,
}
```

Кожен варіант переліку може містити атрибут `#[msg(...)]`, який записує описовий рядок щоразу, коли виникає помилка; набагато корисніше, ніж необроблений числовий код під час налагодження.
