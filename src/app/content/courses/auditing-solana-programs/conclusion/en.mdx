# Conclusion

<ArticleSection name="The Limits of Manual Review" id="the-limits-of-manual-review" level="h2" />

Manual review catches design flaws and logic errors. But edge cases hide in state spaces too large for humans to explore.

A lending protocol with 10 instruction types, each accepting 5 to 8 accounts with various constraints, produces a combinatorial explosion of possible states. A human auditor can trace the most likely paths and the most dangerous sequences, but cannot systematically explore every possible ordering of 10 instructions across every possible account state. A 3-week audit with 2 auditors covers perhaps 70 to 80% of the realistic attack surface. The remaining 20 to 30% is where the next exploit hides.

Consider the bugs that manual review struggles with:

- **Deep multi-instruction sequences** -- An exploit that requires executing 7 specific instructions in a precise order with specific parameters at each step.
- **Numerical edge cases** -- A rounding error that only manifests when the pool balance is between 1,000,000 and 1,000,001 tokens, the price is exactly at a 6-decimal boundary, and the user's share count is a prime number.
- **Cross-transaction state corruption** -- State that is valid after each individual transaction but becomes exploitable when specific transactions land in a specific slot order under parallel execution.

These are not hypothetical scenarios. Real exploits have been found in exactly these categories, often months after manual audits declared the code safe.

<ArticleSection name="What Comes Next" id="what-comes-next" level="h2" />

The next frontier in Solana security is automated tooling. **Fuzzing** generates millions of random instruction sequences and checks for panics, invariant violations, and unexpected state transitions. **Formal verification** uses mathematical proof to demonstrate that a program satisfies specific properties under all possible inputs and states. Neither replaces manual review -- fuzzers need invariants written by humans, and formal verification needs specifications written by humans who understand the protocol's intent. The combination of manual review and automated tools produces the strongest security assurance available.
