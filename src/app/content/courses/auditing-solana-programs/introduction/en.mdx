# Auditing Solana Programs

Solana programs guard billions of dollars in user deposits, LP positions, and protocol reserves. A single missing constraint, one unchecked arithmetic operation, or a misunderstood account relationship can erase all of it in a single block. Auditing is the discipline of finding those flaws before an attacker does.

The preceding courses built a catalog of what to look for: instruction-level validation failures in Program Security, arithmetic and rounding errors in Arithmetic and Accounting, and protocol-level economic exploits in Protocol-Level Attacks. This course teaches you how to systematically find those vulnerabilities in unfamiliar code. Not in the abstract, but through the concrete methodology, tooling, and reporting standards that professional auditors use on real engagements. By the end, you will be able to read unfamiliar Anchor programs, identify vulnerability classes, write proof-of-concept exploits, and produce audit reports that meet industry standards.

<ArticleSection name="What Auditors Actually Do" id="what-auditors-actually-do" level="h2" />

An audit is not a casual code review. It is a structured, time-bounded security assessment with defined scope, deliverables, and accountability. The process follows four distinct phases:

1. **Scoping** -- The auditor and the protocol team agree on which programs, branches, and commit hashes are in scope. A timeline and price are set based on lines of code, complexity, and number of auditors assigned.

2. **Review** -- The auditor reads every instruction handler, traces every state transition, and maps every trust boundary. Findings are logged with severity, description, proof of concept, and recommended fix. This phase typically consumes 70-80% of the total engagement time.

3. **Report** -- Findings are compiled into a structured document with an executive summary, per-finding details, and an overall risk assessment.

4. **Fix Verification** -- The protocol team addresses each finding. The auditor reviews the fixes, confirms they resolve the issue without introducing new vulnerabilities, and issues a final report with the status of each finding (resolved, acknowledged, disputed).

The entire cycle typically takes 2 to 6 weeks depending on codebase size. A 3,000-line Anchor program with moderate DeFi complexity usually requires 2 to 3 auditors working for 2 to 3 weeks.
