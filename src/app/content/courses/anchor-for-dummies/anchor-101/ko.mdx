# Anchor 101

![Introduction to Anchor](/graphics/course-banners/anchor-for-dummies.png)

<ArticleSection name="Anchor란 무엇인가" id="what-is-anchor" level="h2" />

Anchor는 Solana 스마트 컨트랙트 개발을 위한 최고의 프레임워크로, 온체인 프로그램 작성, 테스트, 배포 및 상호 작용을 위한 완벽한 워크플로우를 제공합니다.

### 핵심 장점

- **반복 작업 감소**: Anchor는 계정 관리, instruction serialization, 오류 처리와 같은 반복적인 작업을 추상화하여 핵심 비즈니스 로직에만 집중할 수 있도록 돕습니다.
- **내장된 보안**: 계정 소유권 확인(account-ownership verification) 및 데이터 유효성 검사(data validation)와 같은 엄격한 검사가 기본적으로 실행되어, 많은 일반적인 취약점이 발생하기 전에 완화됩니다.

### Anchor 매크로

- `declare_id!()`: 프로그램이 온체인에서 어느 주소에 위치하는지 선언합니다.
- `#[program]`: 모든 instruction entrypoint와 비즈니스 로직 함수를 포함하는 모듈을 표시합니다.
- `#[derive(Accounts)]`: instruction이 요구하는 account를 나열하고, 해당 제약 조건을 자동으로 적용합니다.
- `#[error_code]`: 디버깅을 더 명확하고 빠르게 만드는 사용자 정의의 읽기 쉬운 오류 타입을 정의합니다.

이러한 절차적 매크로들은 저수준 바이트 관리를 추상화하여, 훨씬 적은 노력으로 안전하고 프로덕션 수준의 Solana 프로그램을 제공할 수 있도록 합니다.

### 프로그램 구조

각 매크로가 실제로 무엇을 하는지 자세히 설명하기 위해 프로그램의 최소한의 버전을 살펴보겠습니다.

```rust
declare_id!("22222222222222222222222222222222222222222222");

#[program]
pub mod blueshift_anchor_vault {
    use super::*;

    pub fn deposit(ctx: Context<VaultAction>, amount: u64) -> Result<()> {
        // ...
        Ok(())
    }

    pub fn withdraw(ctx: Context<VaultAction>) -> Result<()> {
        // ...
        Ok(())
    }
}

#[derive(Accounts)]
pub struct VaultAction<'info> {
    // ...
}

#[error_code]
pub enum VaultError {
    // ...
}
```

이는 모든 것을 `lib.rs`에 몰아넣는 대신, 더 구조화된 프로그램을 위해 집중된 모듈로 변환될 것입니다. 프로그램 폴더 트리는 대략 다음과 같이 보일 것입니다:

```
src
├── instructions
│       ├── instruction1.rs
│       ├── mod.rs
│       ├── instruction2.rs
│       └── instruction3.rs
├── errors.rs
├── lib.rs
└── state.rs
```

#### `declare_id!()`

`declare_id!()` 매크로는 프로그램에 온체인 주소를 할당합니다. 이 주소는 프로젝트의 `target` 폴더에 있는 keypair에서 파생된 고유한 public key입니다. 해당 keypair는 모든 프로그램 로직과 데이터를 포함하는 컴파일된 `.so` 바이너리에 서명하고 배포합니다.

**참고:** Blueshift 예제에서는 내부 테스트 스위트 때문에 플레이스홀더 `222222...`를 사용합니다. 프로덕션 환경에서는 표준 빌드 및 배포 명령을 실행할 때 Anchor가 새로운 program ID를 생성해 줄 것입니다.

#### `#[program]` & `#[derive(Accounts)]`

모든 instruction은 필요한 모든 account와 (선택적으로) 데이터를 나열하는 자체 **Context** struct를 가집니다.

이 예제에서 `deposit`과 `withdraw`는 동일한 account를 공유합니다. 따라서 효율성을 높이고 쉽게 유지하기 위해 `VaultAction`이라는 단일 account struct를 생성할 것입니다.

#### `#[derive(Accounts)]` 매크로 심층 분석

```rust
#[derive(Accounts)]
pub struct VaultAction<'info> {
  #[account(mut)]
  pub signer: Signer<'info>,

  #[account(
    mut,
    seeds = [b"vault", signer.key().as_ref()],
    bump,
  )]
  pub vault: SystemAccount<'info>,

  pub system_program: Program<'info, System>,
}
```

코드 스니펫에서 볼 수 있듯이, `#[derive(Accounts)]` 매크로는 세 가지 중요한 역할을 수행합니다:
- 특정 instruction이 필요로 하는 모든 account를 선언합니다.
- 제약 조건 검사를 자동으로 적용하여 런타임에 많은 버그와 잠재적인 익스플로잇을 차단합니다.
- account에 안전하게 접근하고 변경할 수 있도록 헬퍼 메서드를 생성합니다.

이는 account 타입과 인라인 속성의 조합을 통해 이루어집니다.

**예제에 사용된 account 타입**
- `Signer<'info>`: account가 트랜잭션에 서명했음을 확인합니다. 보안 및 서명을 요구하는 CPI에 필수적입니다.
- `SystemAccount<'info>`: System Program에 의한 account 소유권을 확인합니다.
- `Program<'info, System>`: account가 실행 가능하며 System Program ID와 일치하는지 확인하여, account 생성 또는 lamport 전송과 같은 CPI를 가능하게 합니다.

**접하게 될 인라인 속성**
- `mut`: account를 mutable로 표시합니다. lamport 잔액 또는 데이터가 변경될 수 있을 때마다 필수적입니다.
- `seeds & bump`: account가 제공된 seeds와 bump 바이트로부터 생성된 PDA(Program-Derived Address)인지 확인합니다.

**참고** PDA는 다음과 같은 이유로 중요합니다:
- 소유하는 프로그램에 의해 사용될 때, PDA는 프로그램을 대신하여 CPI에 서명할 수 있습니다.
- 프로그램 상태를 지속하기 위한 결정적이고 검증 가능한 주소를 제공합니다.

#### `#[error_code]`

`#[error_code]` 매크로는 프로그램 내에서 명확한 사용자 정의 오류를 정의할 수 있도록 합니다.

```rust
#[error_code]
pub enum VaultError {
    #[msg("Vault already exists")]
    VaultAlreadyExists,
    #[msg("Invalid amount")]
    InvalidAmount,
}
```

각 enum variant는 오류 발생 시 설명적인 문자열을 기록하는 `#[msg(...)]` 속성을 가질 수 있습니다. 이는 디버깅 중 원시 숫자 코드보다 훨씬 더 유용합니다.
