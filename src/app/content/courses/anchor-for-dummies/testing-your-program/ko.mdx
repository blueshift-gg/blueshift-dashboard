# 프로그램 테스트

철저한 테스트는 재정적 손실을 방지하고, 사용자 신뢰를 구축하며, 프로그램이 모든 조건에서 올바르게 작동하도록 보장합니다.

> 메인넷 배포 전에 철저히 테스트하세요.

<ArticleSection name="TypeScript Tests" id="typescript-tests" level="h2" />

TypeScript 테스트는 dApp 클라이언트에도 TypeScript가 필요하기 때문에 가장 일반적인 접근 방식입니다. 이를 통해 테스트와 클라이언트 코드를 동시에 개발할 수 있습니다.

클라이언트 측 설정에 대해서는 [여기](/en/courses/anchor-for-dummies/client-side-development)에서 자세히 다루었습니다.

> 모든 Anchor CLI 프로젝트에는 테스트를 위한 TypeScript 파일이 포함된 test 폴더가 있습니다.

TypeScript 테스트는 다음과 같은 주요 이점을 제공합니다.
- 실제 클라이언트 상호 작용을 반영합니다.
- 복잡한 워크플로우 및 엣지 케이스를 테스트합니다.
- API 변경 사항에 대한 즉각적인 피드백을 제공합니다.
- 성공 및 오류 시나리오를 검증합니다.

테스트를 실행하려면:

```bash
anchor test
```

> 구성에서 클러스터를 localnet으로 설정하여 로컬넷에서 실행하세요. 이렇게 하면 로컬 Validator가 시작되고 제공자 wallet에 1,000 SOL이 추가됩니다. 데이터가 포함된 추가 account가 필요한 경우, [로컬 Validator 실행](/en/courses/anchor-for-dummies/testing-your-program#running-a-local-validator)을 참조하세요.

<ArticleSection name="Mollusk Tests" id="mollusk-tests" level="h2" />

테스트 환경 또는 복잡한 프로그램 상태 설정에 대한 세밀한 제어가 필요할 때, Mollusk이 해결책을 제공합니다.

Mollusk은 Solana 프로그램 전용으로 구축된 Rust 테스트 프레임워크입니다. 이를 통해 다음을 수행할 수 있습니다.
- 네트워크 오버헤드 없이 프로그램 로직을 격리하여 테스트합니다.
- 복잡한 account 상태를 쉽게 설정합니다.
- 전체 통합 테스트보다 빠르게 테스트를 실행합니다.
- 특정 블록체인 조건 및 엣지 케이스를 모의합니다.

Mollusk 테스트에 대해서는 [여기](/en/courses/testing-with-mollusk)에서 자세히 다루었습니다.

Mollusk으로 새로운 Anchor 프로그램을 생성하려면:

```bash
anchor init <name-of-the-project> --test-template mollusk
```

다음 명령을 사용하여 테스트를 실행합니다.

```bash
anchor test
```

<ArticleSection name="LiteSVM Tests" id="litesvm-tests" level="h2" />

Mollusk처럼 프로그램 상태에 대한 세밀한 제어가 필요하지만 TypeScript 환경에서 필요할 때 LiteSVM이 최적의 솔루션을 제공합니다.

LiteSVM은 테스트 프로세스에서 Solana Virtual Machine을 직접 실행하는 경량 테스트 프레임워크입니다. 이를 통해 다음을 수행할 수 있습니다.
- `solana-program-test`와 같은 기존 프레임워크보다 훨씬 빠르게 테스트를 실행합니다.
- account 상태 및 Sysvar를 정밀하게 조작합니다.
- 여러 언어(TypeScript, Rust, Python)에서 테스트합니다.
- 복잡한 블록체인 조건 및 엣지 케이스를 손쉽게 모의합니다.

LiteSVM은 VM을 테스트 내에 포함시켜 Validator 오버헤드를 제거하고, 테스트 정확도를 희생하지 않으면서 빠른 개발 주기에 필요한 속도를 제공합니다.

LiteSVM 테스트에 대해서는 [여기](/en/courses/testing-with-litesvm)에서 자세히 다루었습니다.

`anchor-litesvm` 패키지를 사용하여 Anchor provider를 설정하고 이전에 보았던 [클라이언트 측 설정](/en/courses/anchor-for-dummies/client-side-development)을 사용할 수 있습니다.

`anchor-litesvm` 패키지를 설치합니다.

```bash
npm install git:https://github.com/LiteSVM/anchor-litesvm
```

그 다음 기본 Anchor provider를 다음과 같이 `LiteSVMProvider`로 변경합니다.

```ts
import { fromWorkspace, LiteSVMProvider } from "anchor-litesvm";

test("anchor", async () => {
	const client = fromWorkspace("target/types/<program-name>.ts");
	const provider = new LiteSVMProvider(client);
	const program = new Program<Puppet>(IDL, provider);

    // program.methods..
})
```

<ArticleSection name="Running a Local Validator" id="running-a-local-validator" level="h2" />

개인 블록체인 샌드박스 역할을 하는 Validator를 사용하여 메인넷 동작을 로컬에서 미러링합니다. 클러스터를 localnet으로 설정하면 이 작업이 자동으로 수행됩니다.

로컬 Validator는 네이티브 프로그램이 사전 설치된 간소화된 Solana 원장을 운영합니다. 기본적으로 테스트 데이터만 저장하며 기존 메인넷 account에 대한 접근 권한이 없어, 확립된 프로토콜과의 테스트가 제한됩니다.

### 로컬 Validator 구성

`Anchor.toml` 파일의 `[test]` 섹션에서 Validator를 사용자 지정합니다.

```
[test]
startup_wait = 10000
```

`startup_wait` 플래그는 Validator 시작을 지연시키며, 여러 account를 복제하여 로드 시간이 길어질 때 유용합니다.

### 메인넷 Account 복제

`[test.validator]` 구성을 사용하여 기존 메인넷 account 및 프로그램을 복제합니다.

```
[test.validator]
url = "https://api.mainnet-beta.solana.com"

[[test.validator.clone]]
address = "7NL2qWArf2BbEBBH1vTRZCsoNqFATTddH6h8GkVvrLpG"
[[test.validator.clone]]
address = "2RaN5auQwMdg5efgCaVqpETBV8sacWGR8tkK4m9kjo5r"
[[test.validator.clone]]
address = "metaqbxxUerdq28cj1RbAWkYQm3ybzjb6a8bt518x1s"
```

`clone` 섹션은 지정된 클러스터에서 account를 복사합니다. account가 "BPF 업그레이드 가능한 로더"에 의해 관리되는 프로그램에 연결될 때, Anchor는 자동으로 관련 프로그램 데이터 account를 복제합니다.

### 로컬 Account 데이터 로드

`account` 플래그를 사용하여 JSON 파일에서 로컬 account를 로드합니다.

```
[[test.validator.account]]
address = "Ev8WSPQsGb4wfjybqff5eZNcS3n6HaMsBkMk9suAiuM"
filename = "some_account.json"
```

이 접근 방식은 미리 구성된 account 상태 또는 메인넷에 존재하지 않는 특정 구성으로 테스트하는 데 매우 효과적입니다.

<ArticleSection name="Running Surfnet" id="running-surfnet" level="h2" />

Cross-Program Invocations (CPIs)에 의존하는 Solana 프로그램을 테스트하려면, 전통적으로 로컬 Validator 섹션에서 보았듯이 개발자가 메인넷에서 account와 프로그램을 덤프해야 했습니다.

이 과정은 몇 개의 account에 대해서는 작동하지만, Jupiter와 같이 40개 이상의 account와 8개 이상의 프로그램에 의존할 수 있는 복잡한 프로그램에 대한 CPI를 테스트할 때는 완전히 불가능해집니다.

Surfnet은 solana-test-validator의 드롭인 대체품으로, 개발자가 요청 시 메인넷 account를 가져와 로컬에서 프로그램을 시뮬레이션할 수 있도록 합니다.

사용하려면 공식 [Installation Page](https://docs.surfpool.run/install)를 사용하여 surfpool을 설치한 다음 다음을 실행합니다.

```bash
surfpool start
```

이제 로컬 Validator를 대상으로 Surfnet에 연결할 수 있습니다.

```ts
import { Connection } from "@solana/web3.js";

const connection = new Connection("http://localhost:8899", "confirmed");
```

Surfnet 설정 및 사용법에 대해서는 [여기](/en/courses/testing-with-surfpool)에서 자세히 다루었습니다.
