# AMMs & The Constant Product Curve

How do you trade tokens without a counterparty?

Traditional exchanges match buyers with sellers. But on-chain, there's no order book, no market maker refreshing quotes, no one on the other side of your trade.

AMMs solve this with a simple idea: replace the counterparty with math: A pool holds two tokens and a formula determines the price meaning you can always trade against the formula, without needing anyone else.

The formula that powers most AMMs is the constant product formula: `x * y = k`

<ArticleSection name="The Constant Product Formula" id="constant-product" level="h2" />

### The Core Idea

A pool holds reserves of two tokens and the product of those reserves must stay constant:

```
x * y = k

x = reserve of token A
y = reserve of token B  
k = constant (the product)
```

When you swap, you actually just deposit one token to withdraw the other. The pool adjusts reserves, but `k` stays the same.

```
Before: 1000 SOL × 100,000 USDC = 100,000,000
After swap: 1010 SOL × 99,010 USDC = 100,000,000 (same k)
```

The constraint `x * y = k` creates a curve and every point on that curve is a valid pool state; Swapping is just moving along the curve.

This formula means that the spot price is actually just the ratio of reserves:

```
Price of SOL = USDC reserves / SOL reserves
            = 100,000 / 1000
            = 100 USDC per SOL
```

If someone buys SOL (removes SOL, adds USDC), there's less SOL and more USDC. This means the ratio changes and "SOL gets more expensive".

<ArticleSection name="The Swap Formula" id="swap-formula" level="h2" />

You might want to sell 10 SOL on a SOL-USDC AMM. How much USDC do you get?

Start with the idea that the product must stay constant.

```
Before swap: x × y = k
After swap:  (x + Δx) × (y - Δy) = k

Where:
  Δx = amount you're adding (10 SOL)
  Δy = amount you're receiving (? USDC)
```

Solving for Δy:

```
(x + Δx) × (y - Δy) = x × y
y - Δy = (x × y) / (x + Δx)
Δy = y - (x × y) / (x + Δx)
Δy = y × Δx / (x + Δx)
```

The swap output formula:

```rust
output = (reserve_out * amount_in) / (reserve_in + amount_in)
```

So if we plug real numbers in the formula:

```
Pool: 1000 SOL, 100,000 USDC
You sell: 10 SOL

output = (100,000 × 10) / (1000 + 10)
       = 1,000,000 / 1010
       = 990.09 USDC
```

Wait, but as we said before the spot price of SOL is determined `USDC reserves / SOL reserves`; this means that we should've got 1,000 USDC but we got only 990.

The missing 10 USDC is what we call **price impact**: the cost of moving along the curve. Bigger trades, with thin liquidity move further along the curve, giving you worse prices.

### Why the Formula Works

The genius of `x * y = k`:

1. **Infinite liquidity**: The curve never touches the axes. You can always trade (though prices get extreme).

2. **Self-correcting prices**: If the pool price diverges from market price, arbitrageurs profit by correcting it.

3. **No counterparty needed**: The math is the market maker.

<ArticleSection name="Fees" id="fees" level="h2" />

As always, crypto is an exercise in mechanism design.

If we didn't add any fees to the AMM, LPs (the main counterparty powering this primitive) would have no incentive to deposit tokens. They would just withdraw the same value with a slightly different token allocation.

Fees fix this. Most AMMs take a cut for LPs before calculating the output:

```rust
const FEE_BPS: u64 = 30;  // 0.3%

let amount_after_fee = amount_in * (10_000 - FEE_BPS) / 10_000;
let output = (reserve_out * amount_after_fee) / (reserve_in + amount_after_fee);
```

The fee stays in the pool. After many swaps, the pool has more total value than what LPs deposited.

> Round output DOWN. Protocol should never give users more than what the math says.

<ArticleSection name="Price Impact & Slippage" id="slippage" level="h2" />

Since the curve is hyperbolic, small trades barely move along it. Large trades in thin liquidity travel far, hitting progressively worse prices.

```
Pool: 1000 SOL, 100,000 USDC (spot price: 100)

Sell 10 SOL:   get 990 USDC   (effective price: 99.0)   -1.0%
Sell 100 SOL:  get 9,091 USDC (effective price: 90.9)   -9.1%
Sell 500 SOL:  get 33,333 USDC (effective price: 66.7)  -33.3%
```

This is a mechanism to protects LPs. If someone could buy unlimited tokens at spot price, they'd drain the pool and suffer from no price discovery and bad flow.

### Slippage Protection

Beyond price impact, there's another mechanism that could give you a worse trade than expected.

Between submitting a transaction and execution, prices can move. This is **slippage**, and most AMMs protect users with this simple check:

```rust
pub fn swap(
    ctx: Context<Swap>,
    amount_in: u64,
    min_out: u64,  // Revert if output is less than this
) -> Result<()> {
    let output = calculate_swap_output(amount_in, reserves);
    
    require!(output >= min_out, SlippageExceeded);
    
    // Execute swap...
}
```

Frontends typically set `min_out` to 99% of expected output (1% slippage tolerance).

<ArticleSection name="Beyond Constant Product" id="beyond-constant-product" level="h2" />

Constant product works for general-purpose trading, but it's not optimal for all assets:

| AMM Type | Best For | Key Insight |
|----------|----------|-------------|
| **Constant Product** (x*y=k) | General pairs | Simple, works everywhere |
| **StableSwap** (Curve) | Pegged assets | 100x less slippage for stablecoins |
| **Concentrated Liquidity** (Uni V3) | High-volume pairs | LPs choose price ranges |
| **Weighted Pools** (Balancer) | Portfolios | Custom ratios like 80/20 |
| **Oracle-Integrated** (GMX) | Perpetuals | Zero slippage, oracle pricing |

Each makes different tradeoffs. Constant product's strength is simplicity: five characters that power billions in daily volume.
