# 엔트리포인트

`entrypoint!()`는 모든 Solana 프로그램이 노출해야 하는 단일 심볼입니다. 이는 Solana 런타임이 로더에서 사용자 코드(program)로 전환되는 지점입니다.

전환하기 전에, 로더는 `instruction`이 필요로 하는 모든 것을 `BPF VM`의 입력 페이지에 저장된 하나의 평평한 `C-style record`로 묶습니다. 그런 다음 매크로가 해당 `record`를 풀어 `Rust`에 세 개의 안전한 `slice`와 `reference`를 전달합니다:
- **program_id**: 현재 실행 중인 `program`의 `pubkey`입니다.
- **accounts**: `AccountInfo record`의 연속된 배열에 대한 포인터와 길이를 포함합니다.
- **instruction_data**: `transaction`에 의해 제공되는 `raw bytes`의 `pointer-plus-length slice`입니다.

이 매크로는 다음 작업을 수행합니다:
- 이 `raw pointer`들을 안전한 `Rust slice`로 변환합니다.
- `panic`을 포착하여 `VM`을 `crash`시키는 대신 깔끔한 `ProgramError::Custom` 코드로 변환합니다.
- 모든 것을 `ProgramResult`를 반환하는 사용자 정의 함수(`process_instruction`이라고 자주 불림)로 전달합니다.

다음은 `Solana loader`가 `entrypoint`로 전환하기 전에 `BPF VM`의 입력 페이지에 배치하는 단일 `flat record`에 대한 설명입니다.

```rust
pub struct Entrypoint {
    account_len: u64,
    account_info: [AccountRaw; account_len]
    instruction_len: u64,
    instruction_data: [u8; instruction_len]
    program_id: [u8; 32],
}
```
- `account_len`: 전달된 `account`의 수입니다.
- `account_info`: `instruction`에 포함된 `raw account record`로, 순서대로 나열됩니다.
- `instruction_len`: 뒤따르는 `instruction data`의 바이트(byte) 수입니다.
- `instruction_data`: `instruction` 자체입니다.
- `program_id`: 실행 중인 `program`의 32바이트 `Pubkey`입니다.

`account_info` 배열의 모든 요소는 동일한 `packed layout`을 따릅니다:

```rust
pub struct AccountRaw {
    is_duplicate: u8,
    is_signer: u8,
    is_writable: u8,
    executable: u8,
    alignment: u32,
    key: [u8; 32],
    owner: [u8; 32],
    lamports: u64,
    data_len: usize,
    data: [u8; data_len],
    padding: [u8; 10_240],
    alignment_padding: [u8; ?],
    rent_epoch: i64,
}
```
- `is_duplicate`: 동일한 `account`가 목록에 두 번 이상 나타나는 경우 건너뛰어 데이터를 다시 `deserialize`하지 않도록 합니다. `0xFF`는 "고유"함을 의미하며, 다른 모든 값은 복사 대상 `index`를 나타냅니다.
- `is_signer` / `is_writable` / `executable`: 런타임이 사용하는 단일 바이트 `flag`로, 추가 `syscall` 없이 `program`이 `logic` 및 `CPI`를 제어할 수 있도록 합니다.
- `alignment`: 전체 `struct`를 8바이트 정렬 상태로 유지하는 4바이트의 플레이스홀더(`placeholder`) 슬롯입니다. `Pinocchio`는 `realloc` 중에 원래 `data length`를 추적하기 위해 이를 재활용합니다.
- `key` / `owner` / `lamports`: 각 `account`가 가져야 할 최소 필수 `data`입니다.
- `data_len` + `data`: `account`가 가질 수 있는 가변 길이 `data`입니다.
- `padding`: 로더는 `account`의 최대 크기인 10,240바이트를 미리 할당하여, `account data`가 메모리를 이동하지 않고도 제자리에서 변경되고 확장될 수 있도록 합니다.
- `alignment_padding`: 필요한 경우 다음 `AccountRaw`가 여전히 8바이트 경계에서 시작하도록 하는 추가 `filler`입니다 (일부 `eBPF host`에 중요).
- `rent_epoch`: `account`가 다음 `rent`를 지불해야 하는 `epoch`입니다; `rent collection`이 일시 중지되었음에도 불구하고 호환성을 위해 유지됩니다.
