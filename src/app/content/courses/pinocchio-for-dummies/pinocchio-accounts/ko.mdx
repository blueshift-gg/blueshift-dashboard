# Accounts

이전 섹션에서 보았듯이, Pinocchio의 account 유효성 검사는 owner, signer, discriminator 검사를 자동으로 수행하는 Account Types를 사용할 수 없기 때문에 Anchor와 다릅니다.

Native Rust에서는 이러한 유효성 검사를 수동으로 수행해야 합니다. 이는 더 많은 세부 사항에 주의를 기울여야 하지만, 구현하기는 간단합니다.

```rust
// SignerAccount 타입
if !account.is_signer() {
    return Err(PinocchioError::NotSigner.into());
}
```

또는 owner 검사의 경우:

```rust
// SystemAccount 타입
if !account.is_owned_by(&pinocchio_system::ID) {
    return Err(PinocchioError::InvalidOwner.into());
}
```

이전에 다룬 `TryFrom` 구현에 모든 유효성 검사를 래핑함으로써, 누락된 검사를 쉽게 식별하고 안전한 코드를 작성하고 있는지 확인할 수 있습니다.

하지만 각 instruction에 대해 이러한 검사를 작성하는 것은 반복적일 수 있습니다. 이를 해결하기 위해 Anchor와 유사한 타입을 정의하여 이러한 유효성 검사를 간소화하는 `helper.rs` 파일을 만들었습니다.

<ArticleSection name="Signer and System Account" id="signer-and-system-account" level="h2" />

이전 예시에서 보았듯이, `SystemAccount` 및 `SignerAccount` 검사는 간단하며 어떠한 추가 유효성 검사도 필요하지 않습니다. 따라서 `helper.rs`에 다음을 추가할 것입니다.

```rust
fn signer_check(account: &AccountInfo) -> Result<(), ProgramError> {
    if !account.is_signer() {
        return Err(PinocchioError::NotSigner.into());
    }

    Ok(())
}

fn system_account_check(account: &AccountInfo) -> Result<(), ProgramError> {
    if !account.is_owned_by(&pinocchio_system::ID) {
        return Err(PinocchioError::InvalidOwner.into());
    }

    Ok(())
}
```

여기서는 단순히 account가 signer인지 또는 system program에 의해 소유되었는지 확인합니다.

<ArticleSection name="Mint and Token Accounts" id="mint-and-token-accounts" level="h2" />

이제 더 흥미로운 부분이 나옵니다. 우리는 일반적인 account 검사(ownership 및 length 검사)로 시작하지만, `init` 및 `init_if_needed`와 같은 Anchor 매크로와 유사한 추가 helper를 제공하기 위해 다른 특정 함수들도 추가합니다.

```rust
pub struct Mint;

impl Mint {
    fn check(account: &AccountInfo) -> Result<(), ProgramError> {
        if !account.is_owned_by(&pinocchio_token::ID) {
            return Err(PinocchioError::InvalidOwner.into());
        }

        if account.data_len() != pinocchio_token::state::Mint::LEN {
            return Err(PinocchioError::InvalidAccountData.into());
        }

        Ok(())
    }

    //...
}
```

`init` 및 `init_if_needed` 기능을 위해 내부적으로 `CreateAccount` 및 `InitializeMint2` CPI를 사용하여 `Mint` account를 초기화합니다.

```rust
impl Mint {
    //...

    fn init(
        account: &AccountInfo,
        payer: &AccountInfo,
        decimals: u8,
        mint_authority: &[u8; 32],
        freeze_authority: Option<&[u8; 32]>
    ) -> ProgramResult {
        // rent에 필요한 lamports를 가져옵니다.
        let lamports = Rent::get()?.minimum_balance(pinocchio_token::state::Mint::LEN);

        // 필요한 lamports로 account에 자금을 조달합니다.
        CreateAccount {
            from: payer,
            to: account,
            lamports,
            space: pinocchio_token::state::Mint::LEN as u64,
            owner: &pinocchio_token::ID,
        }.invoke()?;

        InitializeMint2 {
            mint: account,
            decimals,
            mint_authority,
            freeze_authority,
        }.invoke()
    }

    fn init_if_needed(
        account: &AccountInfo,
        payer: &AccountInfo,
        decimals: u8,
        mint_authority: &[u8; 32],
        freeze_authority: Option<&[u8; 32]>
    ) -> ProgramResult {
        mint_account_check(account) {
            Ok(_) => Ok(()),
            Err(_) => init(account, payer, decimals, mint_authority, freeze_authority),
        }
    }
}
```

### Token2022

Legacy SPL Token Program의 경우, `Mint` 및 `Token` account에 대해 길이 검사만 수행했다는 것을 눈치챘을 수 있습니다. 이러한 접근 방식은 고정된 크기를 가진 두 가지 account 타입만 있을 때, 길이만으로도 서로를 구별할 수 있기 때문에 작동합니다.

Token2022의 경우, 이 간단한 접근 방식은 작동하지 않습니다. token extension이 `Mint` 데이터에 직접 추가되면 `Mint`의 크기가 늘어나 잠재적으로 `Token` account 크기를 초과할 수 있습니다. 이는 account 타입 간의 구분을 위해 오직 크기에만 의존할 수 없음을 의미합니다.

Token2022의 경우, `Mint`와 `Token` account를 두 가지 방식으로 구별할 수 있습니다.
- **크기 기준**: Legacy Token Program과 유사하게 (account가 표준 크기를 가질 때)
- **discriminator 기준**: 165번째 위치에 있는 특수 바이트 (legacy Token account보다 1바이트 커서 충돌을 피함)

이로 인해 유효성 검사가 수정됩니다.

```rust
// TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb
pub const TOKEN_2022_PROGRAM_ID: [u8; 32] = [
    0x06, 0xdd, 0xf6, 0xe1, 0xee, 0x75, 0x8f, 0xde, 0x18, 0x42, 0x5d, 0xbc, 0xe4, 0x6c, 0xcd, 0xda,
    0xb6, 0x1a, 0xfc, 0x4d, 0x83, 0xb9, 0x0d, 0x27, 0xfe, 0xbd, 0xf9, 0x28, 0xd8, 0xa1, 0x8b, 0xfc,
];

const TOKEN_2022_ACCOUNT_DISCRIMINATOR_OFFSET: usize = 165;
pub const TOKEN_2022_MINT_DISCRIMINATOR: u8 = 0x01;
pub const TOKEN_2022_TOKEN_ACCOUNT_DISCRIMINATOR: u8 = 0x02;

pub struct Mint2022;

impl Mint2022 {
    fn check(account: &AccountInfo) -> Result<(), ProgramError> {
        if !account.is_owned_by(&TOKEN_2022_PROGRAM_ID) {
            return Err(PinocchioError::InvalidOwner.into());
        }

        let data = account.try_borrow_data()?;

        if data.len().ne(&pinocchio_token::state::Mint::LEN) {
            if data.len().le(&TOKEN_2022_ACCOUNT_DISCRIMINATOR_OFFSET) {
                return Err(PinocchioError::InvalidAccountData.into());
            }

            if data[TOKEN_2022_ACCOUNT_DISCRIMINATOR_OFFSET].ne(&TOKEN_2022_MINT_DISCRIMINATOR) {
                return Err(PinocchioError::InvalidAccountData.into());
            }
        }

        Ok(())
    }

    fn init(
        account: &AccountInfo,
        payer: &AccountInfo,
        decimals: u8,
        mint_authority: &[u8; 32],
        freeze_authority: Option<&[u8; 32]>
    ) -> ProgramResult {
        // rent에 필요한 lamports를 가져옵니다.
        let lamports = Rent::get()?.minimum_balance(pinocchio_token::state::Mint::LEN);

        // 필요한 lamports로 account에 자금을 조달합니다.
        CreateAccount {
            from: payer,
            to: account,
            lamports,
            space: pinocchio_token::state::Mint::LEN as u64,
            owner: &TOKEN_2022_PROGRAM_ID,
        }.invoke()?;

        InitializeMint2 {
            mint: account,
            decimals,
            mint_authority,
            freeze_authority,
        }.invoke()
    }

    fn init_if_needed(
        account: &AccountInfo,
        payer: &AccountInfo,
        decimals: u8,
        mint_authority: &[u8; 32],
        freeze_authority: Option<&[u8; 32]>
    ) -> ProgramResult {
        match Self::check(account) {
            Ok(_) => Ok(()),
            Err(_) => Self::init(account, payer, decimals, mint_authority, freeze_authority),
        }
    }
}

### Token Interface

Token2022와 Legacy Token Program 모두를 차별 없이 쉽게 사용할 수 있도록 하기 위해 동일한 기본 원칙을 따르는 helper를 만들었습니다.

```rust
pub struct MintInterface;

impl MintInterface {
    fn check(account: &AccountInfo) -> Result<(), ProgramError> {
        if !account.is_owned_by(&TOKEN_2022_PROGRAM_ID) {
            if !account.is_owned_by(&pinocchio_token::ID) {
                return Err(PinocchioError::InvalidOwner.into());
            } else {
                if account.data_len().ne(&pinocchio_token::state::Mint::LEN) {
                    return Err(PinocchioError::InvalidAccountData.into());
                }
            }
        } else {
            let data = account.try_borrow_data()?;

            if data.len().ne(&pinocchio_token::state::Mint::LEN) {
                if data.len().le(&TOKEN_2022_ACCOUNT_DISCRIMINATOR_OFFSET) {
                    return Err(PinocchioError::InvalidAccountData.into());
                }
                if data[TOKEN_2022_ACCOUNT_DISCRIMINATOR_OFFSET].ne(&TOKEN_2022_MINT_DISCRIMINATOR) {
                    return Err(PinocchioError::InvalidAccountData.into());
                }
            }
        }

        Ok(())
    }
}

pub struct TokenInterface;

impl TokenInterface {
    fn check(account: &AccountInfo) -> Result<(), ProgramError> {
        if !account.is_owned_by(&TOKEN_2022_PROGRAM_ID) {
            if !account.is_owned_by(&pinocchio_token::ID) {
                return Err(PinocchioError::InvalidOwner.into());
            } else {
                if account.data_len().ne(&pinocchio_token::state::TokenAccount::LEN) {
                    return Err(PinocchioError::InvalidAccountData.into());
                }
            }
        } else {
            let data = account.try_borrow_data()?;

            if data.len().ne(&pinocchio_token::state::TokenAccount::LEN) {
                if data.len().le(&TOKEN_2022_ACCOUNT_DISCRIMINATOR_OFFSET) {
                    return Err(PinocchioError::InvalidAccountData.into());
                }
                if data[TOKEN_2022_ACCOUNT_DISCRIMINATOR_OFFSET]
                    .ne(&TOKEN_2022_TOKEN_ACCOUNT_DISCRIMINATOR)
                {
                    return Err(PinocchioError::InvalidAccountData.into());
                }
            }
        }

        Ok(())
    }
}

### Associated Token Account

Associated Token Program을 위한 몇 가지 검사를 만들 수 있습니다. 이것들은 일반적인 Token Program 검사와 매우 유사하지만, account가 올바르게 파생되었는지 확인하기 위한 추가 derivation 검사를 포함합니다.

```rust
pub struct AssociatedToken;

impl AssociatedToken {
    fn check(
        account: &AccountInfo,
        authority: &AccountInfo,
        mint: &AccountInfo,
        token_program: &AccountInfo,
    ) -> Result<(), ProgramError> {
        TokenAccount::check(account)?;

        if find_program_address(
            &[authority.key(), token_program.key(), mint.key()],
            &pinocchio_associated_token_account::ID,
        ).0.ne(account.key()) {
            return Err(PinocchioError::InvalidAddress.into());
        }

        Ok(())
    }

    fn init(
        account: &AccountInfo,
        mint: &AccountInfo,
        payer: &AccountInfo,
        owner: &AccountInfo,
        system_program: &AccountInfo,
        token_program: &AccountInfo
    ) -> ProgramResult {
        Create {
            funding_account: payer,
            account,
            wallet: owner,
            mint,
            system_program,
            token_program,
        }.invoke()
    }

    fn init_if_needed(
        account: &AccountInfo,
        mint: &AccountInfo,
        payer: &AccountInfo,
        owner: &AccountInfo,
        system_program: &AccountInfo,
        token_program: &AccountInfo
    ) -> ProgramResult {
        match Self::check(account, payer, mint) {
            Ok(_) => Ok(()),
            Err(_) => Self::init(account, mint, payer, owner, system_program, token_program),
        }
    }
}
```

<ArticleSection name="Program Accounts" id="program-accounts" level="h2" />

마지막으로, `init` 및 `close` 기능을 포함한 program account에 대한 검사 및 helper를 구현합니다.

저희 `close` 구현에서 흥미로운 점을 발견하실 수 있습니다. 저희는 account의 크기를 거의 아무것도 남기지 않고, 첫 번째 바이트만 남겨두고 255로 설정합니다. 이는 재초기화 공격(reinitialization attack)을 방지하기 위한 보안 조치입니다.

재초기화 공격은 공격자가 닫힌 account를 악성 데이터로 재초기화하여 재사용하려고 시도할 때 발생합니다. 첫 번째 바이트를 255로 설정하고 account 크기를 거의 0으로 줄임으로써, 미래에 해당 account가 유효한 account 타입으로 오인될 가능성을 없앱니다. 이는 Solana 프로그램에서 흔히 사용되는 보안 패턴입니다.

```rust
pub struct ProgramAccount;

impl ProgramAccount {
    fn check(account: &AccountInfo) -> Result<(), ProgramError> {
        if !account.is_owned_by(&crate::ID) {
            return Err(PinocchioError::InvalidOwner.into());
        }

        if account.data_len().ne(&crate::state::ProgramAccount::LEN) {
            return Err(PinocchioError::InvalidAccountData.into());
        }

        Ok(())
    }

    fn init<'a, T: Sized>(
        payer: &AccountInfo,
        account: &AccountInfo,
        seeds: &[Seed<'a>],
        space: usize,
    ) -> ProgramResult {
        // rent에 필요한 lamports를 가져옵니다.
        let lamports = Rent::get()?.minimum_balance(space);

        // seeds 슬라이스로 signer를 생성합니다.
        let signer = [Signer::from(seeds)];

        // account를 생성합니다.
        CreateAccount {
            from: payer,
            to: account,
            lamports,
            space: space as u64,
            owner: &crate::ID,
        }
        .invoke_signed(&signer)?;

        Ok(())
    }

    fn close(account: &AccountInfo, destination: &AccountInfo) -> ProgramResult {
        {
            let mut data = account.try_borrow_mut_data()?;
            data[0] = 0xff;
        }

        *destination.try_borrow_mut_lamports()? += *account.try_borrow_lamports()?;
        account.realloc(1, true)?;
        account.close()
    }
}
