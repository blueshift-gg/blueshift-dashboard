# Інструкції

Тепер, коли ви розумієте регістри та області пам'яті sBPF, давайте розглянемо інструкції, які ними маніпулюють.

Інструкції – це фундаментальні операції, які виконує ваша програма: додавання чисел, завантаження з пам'яті або перехід до інших місць.

<ArticleSection name="Що таке інструкції?" id="what-are-instructions" level="h2" />

Інструкції – це основні структурні блоки вашої програми. Уявіть їх як команди, які точно вказують процесору, що робити:
- `add64 r1, r2`: "Додати значення в регістрах `r1` та `r2`, зберегти результат у `r1`"
- `ldxdw r0, [r10 - 8]`: "Завантажити 8 байтів зі стекової пам'яті в регістр `r0`"
- `jeq r1, 42, +3`: "Якщо `r1` дорівнює 42, перестрибнути на 3 інструкції вперед"

Кожна інструкція виконує рівно одну операцію та кодує рівно 8 байтів даних для миттєвого декодування віртуальною машиною.

Інструкції sBPF працюють з різними розмірами даних:
- байт = 8 бітів (1 байт)
- півслово = 16 бітів (2 байти)
- слово = 32 біти (4 байти)
- подвійне слово = 64 біти (8 байт)

Більшість операцій sBPF використовують 64-бітні значення (подвійні слова), оскільки регістри мають 64-бітну довжину, але ви можете завантажувати та зберігати дані меншого розміру, коли це необхідно для ефективності.

<ArticleSection name="Категорії та формат інструкцій" id="instruction-categories-and-format" level="h2" />

Коли ви компілюєте код на Rust, C або асемблері, тулчейн генерує потік інструкцій фіксованої ширини, розміром 8 байт, упакованих у розділ `.text` вашого ELF.

Кожна інструкція має узгоджену структуру, яку віртуальна машина може декодувати за один прохід:

```
   1 byte    4 bits   4 bits     2 bytes         4 bytes
┌──────────┬────────┬────────┬──────────────┬──────────────────┐
│  opcode  │  dst   │  src   │   offset     │      imm         │
└──────────┴────────┴────────┴──────────────┴──────────────────┘
```

- `opcode`: Визначає тип операції. Верхні 3 біти вибирають клас інструкції (арифметична, пам'ять, стрибок, виклик, вихід), тоді як нижчі 5 бітів вказують точний варіант (додавання, множення, завантаження, стрибок-якщо-дорівнює).
- `dst`: Номер регістра призначення (`r0–r10`), де зберігаються результати — арифметичні результати, завантажені значення або повернення допоміжних функцій.
- `src`: Регістр джерела, що забезпечує вхідні дані. Для арифметики з двома операндами (`add r1, r2`) він надає друге значення. Для операцій з пам'яттю він може надати базову адресу. Для безпосередніх варіантів (`add r1, 10`) ці 4 біти складаються в код операції.
- `offset`: Невелике ціле число, яке змінює поведінку інструкції. Для завантаження/збереження воно додається до адреси джерела, щоб досягти `[src + offset]`. Для стрибків це відносна цільова точка розгалуження, виміряна в інструкціях.
- `imm`: Поле безпосереднього значення. Арифметичні операції використовують його для констант (`add r1, 42`), `CALL` використовує його для чисел системних викликів (`sol_log = 16`), а операції з пам'яттю можуть обробляти його як абсолютний вказівник.

### Категорії інструкцій

Різні типи інструкцій використовують ці поля певним чином:

- **Переміщення даних**: Переміщення значень між регістрами та пам'яттю:

```sbpf
mov64 r1, 42           # Введіть безпосереднє значення 42 у r1
                       # opcode=move_imm, dst=1, src=unused, imm=42

ldxdw r0, [r10 - 8]    # Завантажити 8 байтів зі стека в r0
                       # opcode=load64, dst=0, src=10, offset=-8, imm=unused

stxdw [r1 + 16], r0    # Зберегти r0 у пам'яті за адресою [r1 + 16]
                       # opcode=store64, dst=1, src=0, offset=16, imm=unused
```

- **Арифметика**: Виконання математичних операцій:

```sbpf
add64 r1, r2           # r1 = r1 + r2
                       # opcode=add_reg, dst=1, src=2, offset=unused, imm=unused

add64 r1, 100          # r1 = r1 + 100  
                       # opcode=add_imm, dst=1, src=unused, offset=unused, imm=100
```

- **Потік керування**: Зміна послідовності виконання:

```sbpf
ja +5                  # Перейти вперед на 5 інструкцій безумовно
                       # opcode=jump, dst=unused, src=unused, offset=5, imm=unused

jeq r1, r2, +3         # If r1 == r2, перехід на 3 інструкції вперед
                       # opcode=jump_eq_reg, dst=1, src=2, offset=3, imm=unused

jeq r1, 42, +3         # If r1 == 42, перехід на 3 інструкції вперед
                       # opcode=jump_eq_imm, dst=1, src=unused, offset=3, imm=42
```

### Кодування коду операції

Кодування коду операції фіксує кілька фрагментів інформації, окрім простого типу операції:
- Клас інструкції: арифметична, пам'ять, стрибок, виклик тощо.
- Розмір операції: 32-бітні та 64-бітні операції
- Тип джерела: регістр проти негайного значення
- Конкретна операція: додавання проти віднімання, завантаження проти збереження тощо.

Це створює різні коди операції для варіантів інструкцій. Наприклад, `add64 r1, r2` (джерело регістра) використовує інший код операції, ніж `add64 r1, 42` (безпосереднє джерело). Аналогічно, `add64` та `add32` мають різні коди операції для різних розмірів операцій.

Арифметичні операції додатково розрізняють варіанти зі знаком та без знака. `udiv64` обробляє значення як беззнакові (від 0 до 18 квінтильйонів), тоді як `sdiv64` обробляє значення зі знаком (від -9 квінтильйонів до +9 квінтильйонів).

<ArticleSection name="Виконання інструкцій" id="instruction-execution" level="h2" />
Код операції визначає, як віртуальна машина інтерпретує решту полів.

Коли віртуальна машина зустрічає `add64 r1, r2`, вона зчитує код операції та розпізнає це як 64-бітну арифметичну операцію, використовуючи два регістри:

Поле `dst` вказує, що результат поміщається в `r1`, поле `src` визначає `r2` як другий операнд, а поля `offset` та `immediate` ігноруються.

Для `add64 r1, 42` код операції змінюється, щоб вказати на негайну операцію. Тепер `dst` все ще вказує на `r1`, але `src` втрачає значення, а поле `immediate` надає другий операнд (42).

Операції з пам'яттю змістовно поєднують кілька полів:

Для `ldxdw r1, [r2+8]` код операції вказує на 64-бітне завантаження пам'яті, `dst` отримує завантажене значення, `src` надає базову адресу, а `offset` (8) додається для створення кінцевої адреси `r2 + 8`.

Інструкції потоку керування дотримуються тієї ж схеми:

Коли ви записуєте `jeq r1, r2, +5`, код операції кодує умовний перехід, порівнюючи два регістри. Якщо `r1` дорівнює `r2`, віртуальна машина додає `offset` (5) до лічильника програми, перестрибуючи на 5 інструкцій вперед.

> Код операції визначає, які поля є змістовними. Формат інструкції залишається незмінним: код операції вказує, як інтерпретувати кожне поле, усуваючи складні режими адресації або спеціальні випадки.
### Виклики функцій та системні виклики

Механізм викликів sBPF розвивався в різних версіях для кращої зрозумілості та безпеки. До sBPF версії 3, `call imm` виконував подвійну функцію: безпосереднє значення визначало, чи викликається внутрішня функція, чи системний виклик.

Середовище виконання розрізняло ці функції на основі діапазону безпосередніх значень, причому номери системних викликів зазвичай були невеликими додатними цілими числами, такими як 16 для `sol_log`.

Починаючи з sBPF версії 3, інструкції розділялися для явної поведінки. `call` off тепер обробляє внутрішні виклики функцій, використовуючи відносні зміщення, тоді як `syscall imm` явно викликає функції середовища виконання. Таке розділення робить наміри байт-коду чіткими та забезпечує кращу перевірку.

Непрямі виклики через `callx` також розвивалися. У попередніх версіях цільовий регістр кодувався в полі безпосереднього регістра, але починаючи з версії 2, він кодується в полі вихідного регістра для узгодженості із загальним форматом інструкцій.
