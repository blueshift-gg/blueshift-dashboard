# sBPF 레지스터 및 메모리 모델

sBPF 프로그램이 실행될 때, 두 가지 주요 저장 메커니즘을 사용합니다: 프로세서에 내장된 11개의 고속 레지스터와 그 외 모든 것을 저장하는 구조화된 메모리 영역입니다.

<ArticleSection name="Registers" id="registers" level="h2" />

레지스터는 프로세서에 직접 내장된 11개의 번호가 매겨진 저장 공간(`r0`부터 `r10`까지)과 같습니다. 각 레지스터는 단일 64-bit 값을 보유하며 지연 없이 즉각적인 액세스를 제공합니다. `add64 r1, r2`를 실행하면 프로세서는 즉시 두 레지스터에서 값을 검색하여 계산을 수행합니다.

장단점은 간단합니다: 총 11개의 공간만 제공되므로, 현재 활발하게 작업하는 값에 대해 전략적으로 사용해야 합니다.

sBPF는 각 레지스터에 특정 역할을 할당합니다:

| Register | Role                 | Callee-saved?  | Usage Notes                                 |
|----------|----------------------|----------------|---------------------------------------------|
| `r0`     | 반환 값              | No             | 함수 결과, syscall 반환 값                   |
| `r1`     | Input buffer pointer | No             | 진입 시 0x400000000를 가리킴                 |
| `r2-r5`  | Scratch/인수         | No             | 헬퍼 함수 인수, 임시 값                       |
| `r6-r9`  | 범용                 | Yes            | 호출 전반에 걸쳐 보존되어야 함                |
| `r10`    | Frame pointer        | Yes, read-only | 스택 베이스, 직접 수정할 수 없음               |

레지스터 `r6`부터 `r9`는 _callee-saved_입니다. 이는 함수 호출 전반에 걸쳐 해당 값이 유지됨을 의미합니다. 함수 호출이 끝난 후에도 보존되어야 하는 중요한 데이터에 이 레지스터를 사용하세요.

나머지 레지스터(`r0`-`r5`)는 syscall 및 함수 호출 중에 덮어쓰여집니다.

레지스터 `r10`은 frame pointer 역할을 하며, 스택 공간의 베이스를 가리키고 읽기 전용으로 유지되기 때문에 "특별"합니다. `[r10 - 8]` 및 `[r10 - 16]`과 같은 음수 offset을 사용하여 스택 변수에 액세스합니다.

<ArticleSection name="Memory" id="memory" level="h2" />

레지스터가 활발하게 사용되는 값을 보유하는 반면, 메모리는 그 외 모든 것을 저장합니다. sBPF는 모든 프로그램에서 동일한 레이아웃을 가진 고정된 영역으로 메모리를 구성합니다:

| Region | Start Address | Purpose                 | Size/Notes                                             |
|--------|---------------|-------------------------|--------------------------------------------------------|
| Text   | 0x100000000   | 코드 및 읽기 전용 데이터 | 프로그램 바이너리                                      |
| Stack  | 0x200000000   | 지역 변수               | 스택 프레임당 4 KiB, 최대 호출 깊이 64                  |
| Heap   | 0x300000000   | 동적 할당               | 32 KiB                                                 |
| Input  | 0x400000000   | 프로그램 매개변수       | 직렬화된 account 및 instruction 데이터               |

- **text region**은 실행 가능한 코드와 문자열 상수와 같은 읽기 전용 데이터를 포함합니다. `.quad` 지시어로 정의된 데이터는 일반적으로 여기에 있습니다.
- **stack region**은 지역 변수를 저장합니다. `r10`이 스택 베이스를 가리키는 경우, `[r10 - 16]`, `[r10 - 24]` 등과 같은 음수 offset을 사용하여 지역 변수에 액세스합니다.
- **input region**은 프로그램의 매개변수를 포함합니다. 진입 시 `r1`은 이 영역(`0x400000000`)을 가리키며, 이를 통해 프로그램에 전달된 직렬화된 account 데이터 및 instruction 매개변수를 읽을 수 있습니다.

이 고정된 레이아웃은 세 가지 주요 이점을 제공합니다: 프로그램 간의 메모리 격리를 통한 보안, 모든 validator에서 동일한 주소를 통한 결정론, 그리고 알려진 위치에 대한 컴파일러 최적화를 통한 성능입니다.

> 매핑되지 않은 주소에 접근하려 하면 AccessViolation이 발생하고 transaction이 실패합니다.

<ArticleSection name="Using Registers and Memory" id="using-registers-and-memory" level="h2" />

레지스터와 메모리가 실제로 함께 작동하는 방식은 다음과 같습니다:

```sbpf
.globl entrypoint
entrypoint:
    // 진입 시: r1은 0x400000000의 input 데이터를 가리킵니다
    
    ldxdw r0, [r1 + 0]      // input에서 처음 8바이트를 r0에 로드
    mov64 r2, 42            // 42를 레지스터 r2에 저장
    add64 r0, r2            // 더하기: r0 = r0 + r2
    
    stxdw [r10 - 8], r0     // 결과를 스택에 저장
    mov64 r0, 0             // 성공 반환
    exit
```

이 프로그램은 일반적인 패턴을 보여줍니다:
- 레지스터 `r1` (input pointer)을 사용하여 메모리에서 읽기
- 레지스터 `r0`과 `r2`를 사용하여 계산
- 레지스터 `r10` (frame pointer)을 사용하여 스택 메모리에 액세스
- 레지스터 `r0`에 결과 반환

워크플로우는 일관된 패턴을 따릅니다: 메모리에서 레지스터로 데이터를 로드하고, 레지스터로 계산을 수행한 다음, 필요할 때 결과를 메모리에 다시 저장합니다.

### 스택 사용

스택은 `r10`을 frame pointer로 사용하여 현재 스택 프레임의 베이스(가장 높은 주소)를 가리킵니다. 지역 변수는 음수 offset을 사용합니다:

```sbpf
// 스택에 값을 저장
mov64 r0, 42
stxdw [r10 - 8], r0         // 첫 번째 스택 슬롯에 저장

// 다시 로드
ldxdw r1, [r10 - 8]         // 첫 번째 스택 슬롯에서 로드
```

스택 슬롯은 일반적으로 8 bytes 너비이므로, 연속된 변수는 `[r10 - 8]`, `[r10 - 16]`, `[r10 - 24]` 등과 같은 offset을 사용합니다.

### 프로그램 진입 및 종료

프로그램은 `.globl`로 표시된 심볼(일반적으로 entrypoint)에서 실행을 시작합니다. 초기 레지스터 상태는 최소한이며 예측 가능합니다:

```sbpf
.globl entrypoint
entrypoint:
    // 진입 시:
    // r1 = 0x400000000 (input buffer pointer)
    // r10 = 0x200001000 (0x200000000 스택 시작 + 0x1000 4KiB 프레임 크기)
    // r0, r2-r9 = 0 (다른 모든 레지스터는 0으로 초기화됨)

    // 여기에 프로그램 로직

    mov64 r0, 0     // 성공 코드 (0 = SUCCESS)
    exit            // 런타임으로 복귀
```

종료 동작은 호출 깊이에 따라 다릅니다:
- 호출 깊이가 0일 때, exit는 `r0`을 결과 코드로 사용하여 프로그램을 종료합니다.
- 더 깊은 호출 레벨에서는 exit가 return 문처럼 작동하여, caller-saved 레지스터(`r6`-`r9`)와 호출자의 frame pointer(`r10`)를 복원한 후 return address에서 실행을 계속합니다.

런타임은 초기 레지스터 상태 구성 및 최종 반환 처리를 포함하여 암시적 prologue 및 epilogue 코드를 통해 설정 및 해제를 자동으로 처리합니다.
