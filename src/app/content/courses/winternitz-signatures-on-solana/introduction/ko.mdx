# Solana의 윈터니츠 서명

![Winternitz Signatures on Solana](/graphics/course-banners/winternitz-signatures-on-solana.png)

정수 분해나 이산 로그와 같은 수학적 문제에 의존하는 RSA 또는 ECDSA 서명과 달리—이러한 방식은 모두 양자 공격에 취약합니다. 윈터니츠 서명은 암호화 해시 함수의 단방향 속성에서만 보안을 확보합니다.

이 근본적인 차이점은 윈터니츠 서명을 양자 내성 암호(post-quantum cryptography)의 초석으로 만듭니다.

<ArticleSection name="윈터니츠 서명이란?" id="what-is-a-winternitz-signature" level="h2" />

윈터니츠 일회용 서명(Winternitz One-Time Signatures, WOTS)은 1970년대 레슬리 램포트(Leslie Lamport)의 획기적인 연구에서 발전했습니다. 램포트는 복잡한 수학적 가정 없이 암호화 해시 함수만을 사용하여 디지털 서명을 생성할 수 있음을 보여주었습니다.

램포트의 초기 방식은 두 개의 비밀 값(secret value)을 사용하여 단일 비트를 서명했습니다. 비트 `b`를 서명하려면 해시 값 `H₀` (b=0인 경우) 또는 `H₁` (b=1인 경우)의 preimage를 공개합니다. 보안은 전적으로 해시 preimage를 찾는 계산적 불가능성, 즉 해시 출력에서 입력값을 역산하는 것에 의존했습니다.

하지만 램포트 서명은 매우 비효율적이었습니다. `n-bit` 메시지에 서명하려면 `2n`개의 비밀 값(secret value)이 필요했고, `2n`개 값의 서명을 생성했습니다. 256비트 메시지의 경우, 이는 512개의 비밀 값을 관리하고 512개 값의 서명을 생성해야 함을 의미했습니다.

로버트 윈터니츠(Robert Winternitz)는 1990년대에 2진수로 개별 비트를 서명하는 대신, 16진수 또는 256진수와 같이 더 높은 진수에서 더 큰 "자리"(digit)를 서명할 수 있다는 것을 깨달았습니다. 이 혁신은 동일한 보안 보장을 유지하면서 키 및 서명 크기를 획기적으로 줄였습니다.

### 윈터니츠 파라미터 및 기저 표현(Base Representation)

윈터니츠 서명의 핵심 파라미터는 메시지 비트를 그룹화하는 방식을 결정하는 `w`입니다:
- 기저(Base): `b = 2^w`
- 자리 범위(Digit range): 각 자리는 `w` 비트를 나타내며, `0`부터 `2^w - 1`까지의 값을 가질 수 있습니다.

일반적인 파라미터 선택:
- `w = 1`: 각 위치는 1비트를 나타내며 (값 0 또는 1), 2진수 램포트 서명과 동일합니다.
- `w = 4`: 각 위치는 4비트를 나타내며 (값 0-15), 16진수 표현입니다.
- `w = 8`: 각 위치는 8비트를 나타내며 (값 0-255), 256진수 표현입니다.

> `w` 값이 클수록 서명 크기는 작아지지만, 보안을 위해 더 많은 계산이 필요합니다. 이러한 트레이드오프는 WOTS 성능 특성을 이해하는 데 필수적입니다.

### 해시 체인(Hash Chains)

윈터니츠 서명은 해시 체인을 사용합니다. 해시 체인이란 비밀 값에서 시작하여 해시 함수를 반복적으로 적용한 일련의 값입니다: `H⁰(s) = s`, `H¹(s) = H(s)`, `H²(s) = H(H(s))`, ..., `Hⁱ(s) = H(H^(i-1)(s))`

보안 속성은 비대칭적입니다: `Hⁱ(s)`가 주어졌을 때, `j > i`인 `Hʲ(s)`를 계산하는 것은 쉽지만 (단순히 `j-i`번 더 해시하면 됨), `j < i`인 `Hʲ(s)`를 계산하는 것은 해시 함수를 역산해야 하므로 계산적으로 불가능합니다.

### 체크섬 메커니즘(Checksum Mechanism)

체크섬 메커니즘은 특정 유형의 위조 공격을 방지합니다. 체크섬이 없다면 서명을 본 공격자는 메시지를 일부 체인에서 더 많은 해시 연산을 요구하는 형태로 수정하여 해당 구성요소를 위조할 수 있습니다.

체크섬은 모든 체인에 걸쳐 총 "해시 예산"(hash budget)이 일정하게 유지되도록 보장합니다: 공격자가 메시지 자리(digit)를 더 큰 값으로 수정하면 (더 많은 해시가 필요), 체크섬 자리는 자동으로 작아집니다 (다른 값에서 더 적은 해시가 필요하며, 이는 개인 키(private key) 없이는 위조할 수 없습니다).

### 키 생성 프로세스(Key Generation Process)

윈터니츠 파라미터 `w`를 가진 `n`비트 메시지 길이에 대해:

1.  **서명 길이 계산:** 먼저, 어떤 메시지든 표현하는 데 필요한 "청크"(chunk) 수를 파악합니다. 메시지가 256비트 길이고 윈터니츠 파라미터로 `w = 4`를 선택한다면, 총 64개의 청크가 필요합니다: `l₁ = ⌈n/w⌉`. 그런 다음 공식 `l₂ = ⌊log₂(l₁ × (2^w - 1))/w⌋ + 1`을 사용하여 `w = 4`일 때, 최대 체크섬이 960이고 `l₂ = 3`이며, 서명 크기는 `l = l₁ + l₂`가 됩니다.

> 키 생성 시점에는 아직 서명할 메시지를 선택하지 않았기 때문에 체크섬이 무엇이 될지 알 수 없지만, 체크섬을 위해 `l₂`개의 개인 키 구성요소를 예약해야 합니다.

2.  **무작위 시작점 생성:** 필요한 각 해시 체인에 대해 하나의 무작위 비밀 값(secret value)을 생성합니다. 이 무작위 값들이 개인 키 구성요소가 됩니다. 각각을 개별 해시 체인의 "시작점"이라고 생각하십시오: `sk = (sk₁, sk₂, ..., skₗ)`

3.  각 개인 키 구성요소에 대해, 해시 함수를 최대 가능한 횟수(`2^w - 1`)만큼 반복 적용합니다: `pk = (H^(2^w-1)(sk₁), H^(2^w-1)(sk₂), ..., H^(2^w-1)(skₗ))`

### 서명 프로세스(Signing Process)

메시지 `M`에 서명하려면:

1.  메시지를 기저 표현(base representation)으로 변환: `M → (m₁, m₂, ..., m_l₁)` (각 `mᵢ ∈ [0, 2^w - 1]`)

2.  체크섬 계산: `c = Σ((2^w - 1) - mᵢ) for i = 1 to l₁` 후 `c`를 기저 표현(base representation)으로 변환: `c → (c₁, c₂, ..., c_l₂)`

> 해당 메시지에 대한 실제 체크섬 값을 계산하기 위해 적절한 체크섬 개인 키 구성요소를 사용하고 체크섬 자리에 따라 적절한 횟수만큼 해시할 수 있습니다.

3.  서명 생성: 여기서 기저 표현(base representation)은 개인 키(private key)를 해시해야 하는 횟수를 나타냅니다.

### 검증 프로세스(Verification Process)

공개 키 `pk`를 사용하여 메시지 `M`에 대한 서명 σ를 검증하려면:

1.  메시지 표현 재계산: `M → (m₁, m₂, ..., m_l₁)`

2.  체크섬 재계산: `c = Σ((2^w - 1) - mᵢ) → (c₁, c₂, ..., c_l₂)`

3.  각 서명 구성요소에 대해 남은 횟수만큼 해시합니다:
    -   메시지 부분의 경우: `H^((2^w-1)-mᵢ)(σᵢ) = pkᵢ` 검증
    -   체크섬 부분의 경우: `H^((2^w-1)-cⱼ)(σ_(l₁+j)) = pk_(l₁+j)` 검증

> 검증자는 서명자가 멈춘 지점부터 각 해시 체인을 "계속하여", 서명이 유효하면 알려진 공개 키 종착점(endpoint)에 도달합니다.

### 일회용(One-Time) 사용 제한

윈터니츠 서명은 일회용 서명(One-Time Signatures, OTS)입니다. 즉, 각 키 쌍당 한 번만 안전하게 사용할 수 있습니다.

이러한 공격은 다음과 같이 작동합니다: 동일한 개인 키로 여러 메시지에 서명할 때, 해시 체인의 중간 값을 노출하게 됩니다.

체크섬 메커니즘은 일부 메시지 자리(digit)를 증가시키는 것(더 많은 해시)이 체크섬 자리(digit)를 감소시키는 것(더 적은 해시)으로 균형을 이루어야 한다고 요구합니다. 여러 서명이 서로 다른 위치의 중간 값을 노출할 때, 공격자는 더 높은 중간 위치를 사용하여 메시지 구성요소에 대해 더 높은 위치로 이동하고, 동시에 더 낮은 중간 위치를 사용하여 체크섬의 균형을 맞춰 총 해시 예산(hash budget) 제약 조건을 준수하는 위조를 구성할 수 있습니다.

### 양자 내성 보안(Post-Quantum Security)

윈터니츠 서명은 전적으로 해시 함수의 preimage 저항성에서 보안을 확보합니다. 양자 컴퓨터는 RSA 및 ECDSA를 무력화하는 다항 시간 양자 알고리즘(Shor's algorithm)과 달리 SHA-256 또는 SHA-3와 같은 암호화 해시 함수를 효율적으로 역산할 수 없습니다.

적절한 파라미터와 함께 SHA-256을 사용하면 128비트의 양자 내성 보안(post-quantum security)을 제공하여, 양자 시대에도 장기적인 암호화 애플리케이션에 적합한 서명이 됩니다.

<ArticleSection name="Solana의 윈터니츠 서명" id="winternitz-on-solana" level="h2" />

Solana의 현재 암호화 기반은 전적으로 Ed25519 서명에 의존하고 있으며, 이는 쇼어 알고리즘(Shor's algorithm)을 통한 양자 공격에 취약합니다.

양자 컴퓨터가 실용화되면 Solana의 모든 wallet, program authority 및 transaction은 위조 가능해집니다.

양자 내성으로의 마이그레이션(migration)은 하룻밤 사이에 이루어질 수 있는 것이 아닙니다. 시스템은 오늘날 양자 저항성(quantum resistance)을 염두에 두고 설계되어야 하며, 양자 이전(pre-quantum) 세계와 양자 이후(post-quantum) 세계 모두에서 작동하는 하이브리드 접근 방식을 만들어야 합니다.

Solana의 기본 레이어(base layer)는 양자 공격에 취약한 상태로 남아 있지만, 개발자들은 윈터니츠 서명을 사용하여 그 위에 양자 내성 애플리케이션을 구축할 수 있습니다.
