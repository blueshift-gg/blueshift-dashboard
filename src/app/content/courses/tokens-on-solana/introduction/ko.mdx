# Solana의 토큰

![Tokens on Solana](/graphics/course-banners/tokens-on-solana.png)

토큰은 블록체인 네트워크에서 소유권, 접근 권한 또는 가치를 나타내는 디지털 자산입니다. 토큰을 완전히 디지털 형태로 존재하는 프로그래밍 가능한 증명서라고 생각하면 됩니다. 토큰은 돈과 지분에서부터 투표권 및 접근 패스에 이르기까지 모든 것을 나타낼 수 있습니다.

가장 기본적인 수준에서 토큰은 "이 address가 이 asset을 X만큼 소유하고 있다"고 명시하는 블록체인 원장의 entry입니다. 물리적 증명서나 중앙 집중식 데이터베이스를 통해 소유권을 추적해야 하는 전통적인 asset과 달리, 토큰은 블록체인 기술을 사용하여 누가 무엇을 소유하고 있는지에 대한 위변조 방지 및 투명한 기록을 생성합니다.

<ArticleSection name="Why Token Matters" id="why-token-matters" level="h2" />

토큰은 프로그래밍 가능한 소유권을 가능하게 합니다. 누구나 transfer 방식, 부여하는 권리, 또는 다른 시스템과의 상호작용 방식에 대한 custom rule을 사용하여 digital asset을 생성할 수 있습니다.

이는 자동 배당 분배, 조건부 transfer, 또는 사전 정의된 조건에 따라 자동으로 실행되는 복잡한 금융 상품과 같은 가능성을 열어줍니다.

핵심 혁신은 토큰이 중개자 없이 전 세계에 걸쳐 즉시 transfer될 수 있고, 투명하며 (누구나 소유권을 확인할 수 있음), 기본 블록체인의 security guarantee를 유지하면서 정교한 logic으로 프로그래밍될 수 있다는 것입니다.

<ArticleSection name="Different types of Tokens" id="different-types-of-tokens" level="h2" />

토큰은 제공하는 utility 또는 본질적인 characteristics에 따라 다양한 class로 분류될 수 있습니다.

### characteristics 기반

토큰은 "기술적" characteristics에 따라 Fungible과 Non-Fungible의 두 가지 group으로 나뉩니다.

- Fungible Tokens: 상호 교환 가능하다는 의미입니다. 동일한 토큰의 다른 unit으로 대체될 수 있고 fractional unit으로 나눌 수 있는 (예: 0.5 토큰 보유) 여러 개의 동일한 unit으로 구성됩니다.
- Non Fungible Tokens: 고유하며 상호 교환 불가능하다는 의미입니다. 각 토큰은 고유하고 분할 불가능하며 다른 모든 토큰과 구별되는 distinct property를 가집니다.

### utility 기반

이 토큰들이 할 수 있는 기능에 따라 다음과 같은 다른 group이 있습니다:

- Utility Tokens: 제품 또는 서비스에 대한 access를 제공합니다. 예를 들어, 특정 토큰을 보유하면 platform access, 할인된 fee 또는 special feature를 얻을 수 있습니다.
- Governance Tokens: 탈중앙화된 organization에서 holder에게 투표권을 부여합니다. Token holder는 protocol 변경, treasury 지출 또는 기타 결정에 투표할 수 있습니다.
- Security Tokens: 회사 주식, 부동산 또는 원자재와 같은 현실 세계의 asset에 대한 소유권을 디지털 형태로 나타냅니다.
- Stablecoins: 안정적인 가치를 유지하도록 설계된 토큰으로, 일반적으로 US dollar(USDC, USDT)와 같은 currency에 peg됩니다.
- Meme/Community Tokens: 주로 speculation, community building 또는 entertainment value를 위해 존재합니다.

<ArticleSection name="Difference between other Blockchains" id="difference-between-other-blockchains" level="h2" />

Solana에서는 모든 토큰 관련 사항이 [SPL Token Program](https://github.com/solana-program/token)과 [Token2022 Program](/en/courses/token-2022-program)에 의해 처리됩니다. 이는 모든 토큰이 생성, 관리 및 transfer되는 방식을 정의하는 Solana의 native token framework입니다.

이는 network 전반의 모든 token operation을 처리하는 단일의 통합된 program으로, consistency와 interoperability를 보장합니다.

> Solana의 모든 토큰에 대해 단일의 통합된 interface를 갖는다는 결정은 모든 dApps(탈중앙화 애플리케이션) 및 integration(wallet 등)에 걸쳐 복제될 수 있는 쉬운 implementation을 생성합니다.

transaction을 추적하는 블록체인 시스템과 달리, Solana는 Account-Based Model을 가집니다. 이는 account state를 추적한다는 의미입니다. 각 token holding에 대해 해당 토큰의 balance와 ownership을 저장하는 specific account가 있습니다.

이 모든 account 간의 관계는 다음과 같습니다:
- `Mint`: 모든 토큰 유형은 토큰의 configuration: 총 `supply`, `decimal`, `mintAuthority`, `freezeAuthority`를 포함하는 고유한 "mint" account를 가집니다. 이는 Solana에서 토큰의 "출생 증명서" 역할을 합니다.
- `Token`: 각 owner에 대해 특정 토큰의 balance를 보유하는 account입니다. 주요 wallet address(SOL을 보유함)와 달리, 보유하려는 각기 다른 유형의 토큰마다 별도의 token account가 필요합니다. 이는 다른 currency를 위한 별도의 주머니를 갖는 것과 같다고 생각하면 됩니다.
- `Associated Token`: Solana에서 토큰을 보유하는 표준 방식입니다. 이는 `owner`의 address와 `Mint`의 address를 결합하는 결정론적 address generation을 통해 주요 wallet address에 영구적으로 link되어 "associated"된 일반 `Token` account입니다.

### Ethereum과의 차이점

각 토큰에 대해 Ethereum은 모든 token logic, state management 및 transfer rule을 포함하는 완전한 smart contract를 배포해야 합니다.

대부분의 토큰이 호환성을 위해 `ERC-20` standard를 따르지만, 각 토큰은 본질적으로 custom code를 가진 자체 mini-program입니다.

contract address가 토큰의 identifier가 되며, 모든 balance는 내부적인 balance mapping을 가진 해당 contract의 state 내에 저장됩니다.

> 이는 축복이자 저주입니다. 개발자에게 모든 요구 사항을 해결하지 못하는 standard implementation에 의존하지 않고 custom component를 생성할 가능성을 제공하지만, 동시에 bug를 유발하고 통합 및 상호작용하기 어려운 다른 interface를 제공할 수 있습니다.

Ethereum에서는 `Token Factory` 개념이 매우 인기가 있습니다. 이는 다른 토큰을 생성하는 smart contract 또는 program입니다. 개별 token contract를 수동으로 배포하거나 mint account를 하나씩 생성하는 대신, token factory는 표준화된 interface를 통해 토큰 생성 process를 자동화합니다.

이는 다음을 통해 이루어집니다:

- Template-Based Creation: factory는 토큰 생성을 위한 미리 작성된 code template 또는 표준화된 procedure를 포함합니다. 새로운 토큰을 원할 때, factory에 parameter(name, symbol, supply 등)를 제공하면 토큰을 생성해줍니다.
- Batch Processing: factory는 단일 transaction 또는 process에서 여러 토큰을 생성할 수 있어 개별 생성보다 효율적입니다.
- Standardized Output: 동일한 factory에 의해 생성된 모든 토큰은 동일한 pattern과 standard를 따르므로 consistency와 compatibility를 보장합니다.

Solana에서는 `Token Factory`가 SPL Token program 자체이기 때문에 이것이 필요하지 않습니다.

### Bitcoin과의 차이점

Bitcoin은 native token creation mechanism이 없습니다. 토큰은 overlay protocol 또는 `Ordinals` 및 `BRC-20`과 같은 새로운 접근 방식을 사용하여 Bitcoin 위에 구축되어야 합니다. 이러한 방법은 `OP_RETURN` output을 사용하여 Bitcoin transaction에 토큰 data를 embed하거나 satoshi에 직접 data를 inscribe합니다.

> Bitcoin network 자체는 이를 토큰으로 인식하지 않습니다. 추가 data가 있는 Bitcoin transaction으로만 봅니다.

transfer는 Bitcoin network fee와 token transfer를 나타내는 추가 data를 모두 포함하는 Bitcoin transaction 생성을 요구합니다. overlay protocol의 경우, transaction data에 token transfer instruction을 embed하면서 소량의 Bitcoin을 보내는 것과 같습니다.

Bitcoin network는 이를 일반 Bitcoin transaction으로 처리하며, specialized software가 embed된 token data를 해석합니다.
