# 민트 및 토큰 계정

이전 섹션에서 언급했듯이, `SPL Token` 프로그램의 구성 요소는 `account`입니다. 즉, `token`에 대한 모든 정보를 나타내는 `mint account`와 특정 `token`의 소유권에 대한 모든 정보를 나타내는 `token account`입니다.

각 고유한 `mint`마다, 해당 `token`의 보유자가 `ledger`에 얼마나 많은지를 나타내는 수천 개의 다른 `token account`가 존재합니다.

이 섹션에서는 이러한 다양한 `account`에 대해 더 심층적으로 이야기할 것입니다:

<ArticleSection name="The Mint Account" id="the-mint-account" level="h2" />

`Solana`의 `token`은 `Token Program`이 소유하는 `Mint Account`의 `address`로 고유하게 식별됩니다. 이 `account`는 특정 `token`의 전역 카운터 역할을 하며 다음과 같은 `data`를 저장합니다:
- Supply: `token`의 총 공급량
- Decimals: `token`의 소수점 정밀도
- Mint authority: `token`의 새 단위를 생성하여 `supply`를 늘릴 권한이 있는 `account`
- Freeze authority: `Token Account`에서 `token`을 `freeze`하여 전송 또는 `burn`을 방지할 권한이 있는 `account`

이 `data`는 `on-chain`에서 다음과 같이 보입니다:

```rust
pub struct Mint {
    /// Optional authority used to mint new tokens. The mint authority may only
    /// be provided during mint creation. If no mint authority is present
    /// then the mint has a fixed supply and no further tokens may be
    /// minted.
    pub mint_authority: COption<Pubkey>,
    /// Total supply of tokens.
    pub supply: u64,
    /// Number of base 10 digits to the right of the decimal place.
    pub decimals: u8,
    /// Is `true` if this structure has been initialized
    pub is_initialized: bool,
    /// Optional authority to freeze token accounts.
    pub freeze_authority: COption<Pubkey>,
}
```

### Metadata

`explorer`와 `wallet`에서는 `token`이 일반적으로 특정 이름과 연결된 `image` 덕분에 식별 가능하고 사람이 읽을 수 있는 형태로 나타납니다.

우리는 이 이름, `symbol` 및 `image`를 `token`의 `Metadata`라고 부릅니다. `native` 형태의 `Mint` `account`는 사람이 읽을 수 있는 정보가 첨부되지 않은 단지 32 `bytes` 길이의 `public key`일 뿐이기 때문입니다.

`native` 방식으로는, 기존 `SPL Token` 프로그램에서 `token`에 `metadata`를 직접 설정하는 것은 불가능합니다. 이러한 이유로, [Metaplex](https://www.metaplex.com/)와 같은 `protocol`은 모든 `token`이 관련 `metadata`를 가질 수 있는 방법을 제공하기 위해 [MPL-token-metadata](https://github.com/metaplex-foundation/mpl-token-metadata) 프로그램을 개발했습니다.

> `Token Extensions` 및 [`Token2022 program`](/en/courses/token-2022-program)을 통해, 이것은 완전히 달라집니다. `Metadata extension`은 `metadata`를 `mint account` 자체에 직접 포함할 수 있도록 하여, 외부 `program`의 필요성을 없앱니다.

### 대체 불가능 토큰

`token`의 `utility`는 전적으로 `creator`에게 위임되어 있으며, `creator`는 특정 `token`을 `governance token`, `utility token` 또는 `community token`으로 만들지 결정할 수 있지만, `fungible token`과 `non-fungible token`을 구별하기 위해 따를 수 있는 몇 가지 특징이 있습니다:

`대체 불가능 토큰`은 다음을 가져야 합니다:
- 고유하므로 `supply`는 1이어야 합니다.
- 분할 불가능하므로 `decimals`는 0이어야 합니다.
- 동일한 특성을 가진 `token`을 더 추가하는 것을 원치 않으므로 (`token`의 고유성을 "파괴"할 것이기 때문에) `mint authority`는 없어야 합니다.

`native` 방식으로는 `Token program`에서 이러한 특성을 강제하는 것은 불가능합니다. 이러한 이유로, `MPL-token-metadata`와 같은 `program`은 `metadata`에 대한 구현을 제공할 뿐만 아니라, 이러한 제약 조건을 강제하고 `NFT`를 쉽게 생성할 수 있는 구현도 제공합니다.

<ArticleSection name="The Token Account" id="the-token-account" level="h2" />

`Token Program`은 각 `token` 단위의 개별 소유권을 추적하기 위해 `Token Account`를 생성합니다. `Token Account`는 다음과 같은 `data`를 저장합니다:
- Mint: `Token Account`가 보유하는 `token`
- Owner: `Token Account`에서 `token`을 전송할 권한이 있는 `account`
- Amount: `Token Account`가 현재 보유하는 `token`의 수량

이 `data`는 `on-chain`에서 다음과 같이 보입니다:

```rust
pub struct Account {
    /// The mint associated with this account
    pub mint: Pubkey,
    /// The owner of this account.
    pub owner: Pubkey,
    /// The amount of tokens this account holds.
    pub amount: u64,
    /// If `delegate` is `Some` then `delegated_amount` represents
    /// the amount authorized by the delegate
    pub delegate: COption<Pubkey>,
    /// The account's state
    pub state: AccountState,
    /// If is_native.is_some, this is a native token, and the value logs the
    /// rent-exempt reserve. An Account is required to be rent-exempt, so
    /// the value is used by the Processor to ensure that wrapped SOL
    /// accounts do not drop below this threshold.
    pub is_native: COption<u64>,
    /// The amount delegated
    pub delegated_amount: u64,
    /// Optional authority to close the account.
    pub close_authority: COption<Pubkey>,
}
```

각 `wallet`은 보유하고자 하는 각 `token (mint)`에 대해 `token account`를 가져야 하며, `wallet address`가 `token account owner`로 설정되어야 합니다. 각 `wallet`은 동일한 `token (mint)`에 대해 여러 `token account`를 소유할 수 있지만, `token account`는 하나의 `owner`만 가질 수 있고 하나의 `token (mint)` 단위만 보유할 수 있습니다.

<ArticleSection name="The Associated Token Account" id="the-associated-token-account" level="h2" />

`Associated Token Accounts`는 특정 `mint`와 `owner`에 대한 `token account`의 `address`를 찾는 과정을 간소화합니다. `Associated Token Account`를 특정 `mint`와 `owner`를 위한 "기본" `token account`라고 생각할 수 있습니다.

`Associated Token Account`는 `owner`의 `address`와 `mint account`의 `address`에서 파생된 `address`로 생성됩니다. `Associated Token Account`는 특정 `address`를 가진 `token account`에 불과하다는 것을 이해하는 것이 중요합니다.

이것은 `Solana` 개발의 핵심 개념인 [Program Derived Address](https://solana.com/docs/core/pda) (`PDA`)를 소개합니다. `PDA`는 미리 정의된 `input`을 사용하여 `address`를 결정론적으로 파생시키며, 이를 통해 `account`의 `address`를 쉽게 찾을 수 있습니다.
