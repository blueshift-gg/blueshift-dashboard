# 볼트

볼트는 사용자가 자산을 안전하게 보관할 수 있도록 합니다. 볼트는 DeFi의 기본 구성 요소로, 핵심적으로 사용자가 자산(이 경우 lamport)을 안전하게 보관하고 나중에 동일한 사용자만 인출할 수 있도록 합니다.

이 챌린지에서는 기본 계정, 프로그램 파생 주소(PDA), 크로스 프로그램 호출(CPI) 작업 방법을 보여주는 간단한 lamport 볼트를 구축합니다. Anchor에 익숙하지 않다면 [Anchor 소개](/en/courses/introduction-to-anchor)를 먼저 읽고 이 프로그램에서 사용할 핵심 개념을 익히시기 바랍니다.

<ArticleSection name="설치" id="installation" level="h2" />

시작하기 전에 Rust와 Anchor가 설치되어 있는지 확인하세요(필요한 경우 [공식 문서](https://www.anchor-lang.com/docs/installation) 참조). 그런 다음 터미널에서 다음을 실행하세요:

```bash
anchor init blueshift_anchor_vault
```

이 챌린지에는 추가 크레이트가 필요하지 않으므로 이제 새로 생성된 폴더를 열면 코딩을 시작할 준비가 완료됩니다!

<ArticleSection name="템플릿" id="template" level="h2" />

기본 프로그램 구조부터 시작하겠습니다. 이것은 간단한 프로그램이므로 `lib.rs`에 모든 것을 구현하겠습니다. 다음은 필요한 핵심 구성 요소가 포함된 초기 템플릿입니다:

```rust
declare_id!("22222222222222222222222222222222222222222222");

#[program]
pub mod blueshift_anchor_vault {
    use super::*;

    pub fn deposit(ctx: Context<VaultAction>, amount: u64) -> Result<()> {
        // deposit logic
        Ok(())
    }

    pub fn withdraw(ctx: Context<VaultAction>) -> Result<()> {
        // withdraw logic
        Ok(())
    }
}

#[derive(Accounts)]
pub struct VaultAction<'info> {
    #[account(mut)]
    pub signer: Signer<'info>,
    #[account(
        mut,
        seeds = [b"vault", signer.key().as_ref()],
        bump,
    )]
    pub vault: SystemAccount<'info>,
    pub system_program: Program<'info, System>,
}

#[error_code]
pub enum VaultError {
    // error enum
}
```

**참고**: 프로그램을 테스트하기 위해 내부적으로 사용하므로 프로그램 ID를 `22222222222222222222222222222222222222222222`로 변경하는 것을 잊지 마세요.

<ArticleSection name="계정" id="accounts" level="h2" />

두 명령어 모두 동일한 계정을 사용하므로 더 쉽고 읽기 쉽게 만들기 위해 `VaultAction`라는 하나의 컨텍스트를 생성하고 `deposit`와 `withdraw` 모두에 사용할 수 있습니다.

`VaultAction` 계정 구조체에는 다음이 필요합니다:
- `signer`: 볼트의 소유자이며 볼트를 생성한 후 lamport를 인출할 수 있는 유일한 사람입니다.
- `vault`: 다음 시드에서 파생된 PDA: `[b"vault", signer.key().as_ref()]` 서명자의 lamport를 보유합니다.
- `system_program`: 시스템 프로그램에서 전송 명령어 CPI를 사용할 것이므로 포함되어야 하는 시스템 프로그램 계정

계정 구조체를 다음과 같이 정의합니다:

```rust
#[derive(Accounts)]
pub struct VaultAction<'info> {
    #[account(mut)]
    pub signer: Signer<'info>,
    #[account(
        mut,
        seeds = [b"vault", signer.key().as_ref()],
        bump,
    )]
    pub vault: SystemAccount<'info>,
    pub system_program: Program<'info, System>,
}
```

각 계정 제약 조건을 살펴보겠습니다:

1. `signer`: 전송 중에 lamports를 수정할 것이므로 `mut` 제약 조건이 필요합니다.
2. `vault`:
    - lamports를 수정할 것이므로 `mut`가 필요합니다.
    - `seeds` 및 `bumps`는 시드에서 유효한 PDA를 도출하는 방법을 정의합니다.
3. `system_program`: 계정이 실행 가능으로 설정되어 있고 주소가 시스템 프로그램 주소인지 확인합니다.

<ArticleSection name="Errors" id="errors" level="h2" />

이 작은 프로그램에는 많은 오류가 필요하지 않으므로 2개의 열거형만 생성합니다:
- `VaultAlreadyExists`: 계정에 이미 lamports가 있는지 알려주며, 이는 볼트가 이미 존재한다는 것을 의미합니다.
- `InvalidAmount`: 기본 계정의 최소 렌트보다 적은 금액은 입금할 수 없으므로 금액이 그보다 큰지 확인합니다.

다음과 같이 표시됩니다:

```rust
#[error_code]
pub enum VaultError {
    #[msg("Vault already exists")]
    VaultAlreadyExists,
    #[msg("Invalid amount")]
    InvalidAmount,
}
```

<ArticleSection name="Deposit" id="deposit" level="h2" />

입금 명령은 다음 단계를 수행합니다:
1. 이중 입금을 방지하기 위해 볼트가 비어 있는지(lamports가 0인지) 확인합니다
2. 입금 금액이 `SystemAccount`의 렌트 면제 최소값을 초과하는지 확인합니다
3. 시스템 프로그램에 대한 CPI를 사용하여 서명자에서 볼트로 lamports를 전송합니다

먼저 이러한 검사를 구현해 보겠습니다:

```rust
// Check if vault is empty
require_eq!(ctx.accounts.vault.lamports(), 0, VaultError::VaultAlreadyExists);

// Ensure amount exceeds rent-exempt minimum
require_gt!(amount, Rent::get()?.minimum_balance(0), VaultError::InvalidAmount);
```

두 개의 `require` 매크로는 커스텀 가드 절처럼 작동합니다:
- `require_eq!`는 볼트가 비어 있는지 확인합니다(이중 입금 방지).
- `require_gt!`는 금액이 렌트 면제 임계값을 초과하는지 확인합니다.

검사를 통과하면 Anchor의 시스템 프로그램 헬퍼가 다음과 같이 `Transfer` CPI를 호출합니다:

```rust
use anchor_lang::system_program::{transfer, Transfer};

transfer(
    CpiContext::new(
        ctx.accounts.system_program.to_account_info(),
        Transfer {
            from: ctx.accounts.signer.to_account_info(),
            to: ctx.accounts.vault.to_account_info(),
        },
    ),
    amount,
)?;
```

<ArticleSection name="Withdraw" id="withdraw" level="h2" />

출금 명령어는 다음 단계를 수행합니다:
1. 볼트에 램포트가 포함되어 있는지(비어 있지 않은지) 확인합니다
2. 볼트의 PDA를 사용하여 자체적으로 전송에 서명합니다
3. 볼트에서 서명자에게 모든 램포트를 다시 전송합니다

먼저 볼트에 출금할 램포트가 있는지 확인해 보겠습니다:

```rust
// Check if vault has any lamports
require_neq!(ctx.accounts.vault.lamports(), 0, VaultError::InvalidAmount);
```

그런 다음 PDA 서명자 시드를 생성하고 전송을 수행해야 합니다:

```rust
// Create PDA signer seeds
let signer_key = ctx.accounts.signer.key();
let signer_seeds = &[b"vault", signer_key.as_ref(), &[ctx.bumps.vault]];

// Transfer all lamports from vault to signer
transfer(
    CpiContext::new_with_signer(
        ctx.accounts.system_program.to_account_info(),
        Transfer {
            from: ctx.accounts.vault.to_account_info(),
            to: ctx.accounts.signer.to_account_info(),
        },
        &[&signer_seeds[..]]
    ),
    ctx.accounts.vault.lamports()
)?;
```

이 출금의 보안은 두 가지 요소에 의해 보장됩니다:
1. 볼트의 PDA는 서명자의 공개 키를 사용하여 파생되므로 원래 예금자만 출금할 수 있습니다
2. PDA의 전송 서명 능력은 `CpiContext::new_with_signer`에 제공하는 시드를 통해 검증됩니다
