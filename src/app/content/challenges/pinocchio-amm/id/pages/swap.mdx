# Swap

Instruksi `swap` masih menjalankan dua tugas utama yang sama:

- Menghitung berapa banyak token lawan yang harus diterima pengguna, termasuk fee.
- Memindahkan token masuk ke pool dan keluar dari pool.

Yang berubah adalah cara kita berbicara dengan token program. `p-token` sudah live di mainnet dan mempertahankan program ID serta alur client yang sama, sehingga kita bisa membungkus beberapa operasi token ke dalam satu CPI.

<ArticleSection name="Akun yang Diperlukan" id="required-accounts" level="h2" />

Berikut akun-akun yang diperlukan untuk konteks ini:

- `user`: Pengguna yang melakukan swap ke dalam AMM. Harus berupa `signer`.
- `user_x_ata`: Associated token account milik pengguna untuk token X. Harus dikirim sebagai `mutable`.
- `user_y_ata`: Associated token account milik pengguna untuk token Y. Harus dikirim sebagai `mutable`.
- `vault_x`: Token account yang menyimpan token X milik pool. Harus dikirim sebagai `mutable`.
- `vault_y`: Token account yang menyimpan token Y milik pool. Harus dikirim sebagai `mutable`.
- `config`: Account konfigurasi AMM. Menyimpan state dan parameter pool.
- `token_program`: Account token program. `p-token` sudah live di mainnet, mempertahankan program ID SPL Token dan permukaan client yang sama, serta mendukung batching. Harus `executable`.

Parser account-nya tetap sama:

```rust
pub struct SwapAccounts<'a> {
    pub user: &'a AccountInfo,
    pub user_x_ata: &'a AccountInfo,
    pub user_y_ata: &'a AccountInfo,
    pub vault_x: &'a AccountInfo,
    pub vault_y: &'a AccountInfo,
    pub config: &'a AccountInfo,
    pub token_program: &'a AccountInfo,
}

impl<'a> TryFrom<&'a [AccountInfo]> for SwapAccounts<'a> {
    type Error = ProgramError;

    fn try_from(accounts: &'a [AccountInfo]) -> Result<Self, Self::Error> {
        //..
    }
}
```

<ArticleSection name="Data Instruksi" id="instruction-data" level="h2" />

Data instruksinya juga tetap sama:

- `is_x`: Menunjukkan apakah pengguna menukar X ke Y atau Y ke X. Harus berupa `[u8]`.
- `amount`: Jumlah yang ingin dikirim pengguna. Harus berupa `[u64]`.
- `min`: Jumlah minimum yang ingin diterima pengguna. Harus berupa `[u64]`.
- `expiration`: Timestamp setelah order tidak lagi valid. Harus berupa `[i64]`.

Kita bisa mempertahankan layout yang sama:

```rust
pub struct SwapInstructionData {
    pub is_x: bool,
    pub amount: u64,
    pub min: u64,
    pub expiration: i64,
}

impl<'a> TryFrom<&'a [u8]> for SwapInstructionData {
    type Error = ProgramError;

    fn try_from(data: &'a [u8]) -> Result<Self, Self::Error> {
        //..
    }
}
```

> Pastikan `amount` dan `min` keduanya lebih besar dari nol, dan tolak order yang sudah kedaluwarsa menggunakan sysvar `Clock`.

<ArticleSection name="Logika Instruksi" id="instruction-logic" level="h2" />

Kita mulai dengan melakukan deserialisasi terhadap `instruction_data` dan `accounts`.

Lalu kita perlu:

- memuat account `Config` dengan `Config::load()`,
- memverifikasi bahwa state pool adalah `AmmState::Initialized`,
- memverifikasi bahwa `vault_x` dan `vault_y` adalah associated token account yang benar,
- mendeserialisasi token account vault dan menghitung hasil swap dengan `constant-product-curve`.

Perhitungan tersebut tetap seperti ini:

```rust
let vault_x = unsafe { TokenAccount::from_account_info_unchecked(self.accounts.vault_x)? };
let vault_y = unsafe { TokenAccount::from_account_info_unchecked(self.accounts.vault_y)? };

let mut curve = ConstantProduct::init(
    vault_x.amount(),
    vault_y.amount(),
    vault_x.amount(),
    config.fee(),
    None,
)
.map_err(|_| ProgramError::Custom(1))?;

let p = match self.instruction_data.is_x {
    true => LiquidityPair::X,
    false => LiquidityPair::Y,
};

let swap_result = curve
    .swap(p, self.instruction_data.amount, self.instruction_data.min)
    .map_err(|_| ProgramError::Custom(1))?;

if swap_result.deposit == 0 || swap_result.withdraw == 0 {
    return Err(ProgramError::InvalidArgument);
}
```

Perubahan penting ada pada langkah transfer. Kamu sudah melihat pattern batch di `deposit`, jadi masukkan kedua transfer ke dalam `Batch` dan invoke token program satu kali. Untuk swap ini, karena PDA `config` harus menandatangani transfer dari vault, gunakan `batch.invoke_signed(&[signer])?;`.

Sekarang Anda harus memperbarui logika akhir `process()` sehingga:

- validasi dan perhitungan dilakukan lebih dulu,
- kedua instruksi `Transfer` dimasukkan ke dalam batch,
- lalu batch dipanggil sekali ke token program di bagian akhir.

Bentuk instruksi luarnya tetap sama:

```rust
pub struct Swap<'a> {
    pub accounts: SwapAccounts<'a>,
    pub instruction_data: SwapInstructionData,
}

impl<'a> TryFrom<(&'a [u8], &'a [AccountInfo])> for Swap<'a> {
    type Error = ProgramError;

    fn try_from((data, accounts): (&'a [u8], &'a [AccountInfo])) -> Result<Self, Self::Error> {
        let accounts = SwapAccounts::try_from(accounts)?;
        let instruction_data = SwapInstructionData::try_from(data)?;

        Ok(Self {
            accounts,
            instruction_data,
        })
    }
}

impl<'a> Swap<'a> {
    pub const DISCRIMINATOR: &'a u8 = &3;

    pub fn process(&mut self) -> ProgramResult {
        //..

        Ok(())
    }
}
```
