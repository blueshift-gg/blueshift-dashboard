# Swap

L'instruction `swap` effectue toujours les deux mêmes tâches de haut niveau :

- Calculer combien de jetons opposés l'utilisateur doit recevoir, frais inclus.
- Déplacer les jetons vers la pool et hors de la pool.

Ce qui change, c'est la manière de parler au token program. `p-token` est déjà en ligne sur mainnet et conserve le même program ID et flux client, donc nous pouvons regrouper plusieurs opérations token dans un seul CPI.

<ArticleSection name="Comptes Nécessaires" id="required-accounts" level="h2" />

Voici les comptes nécessaires pour ce contexte :

- `user` : l'utilisateur qui effectue le swap dans l'AMM. Doit être `signer`.
- `user_x_ata` : le compte de jetons associé de l'utilisateur pour le jeton X. Doit être passé comme `mutable`.
- `user_y_ata` : le compte de jetons associé de l'utilisateur pour le jeton Y. Doit être passé comme `mutable`.
- `vault_x` : le compte de jetons qui détient le jeton X pour la pool. Doit être passé comme `mutable`.
- `vault_y` : le compte de jetons qui détient le jeton Y pour la pool. Doit être passé comme `mutable`.
- `config` : le compte de configuration de l'AMM. Il stocke l'état et les paramètres de la pool.
- `token_program` : le compte du token program. `p-token` est déjà sur mainnet, conserve le même program ID et la même surface client que SPL Token, et supporte le batching. Doit être `executable`.

Le parseur de comptes reste inchangé :

```rust

    pub vault_y: &'a AccountInfo,
    pub config: &'a AccountInfo,

}
```

<ArticleSection name="Données d'Instruction" id="instruction-data" level="h2" />

Les données d'instruction restent elles aussi inchangées :

- `is_x` : indique si l'utilisateur échange X contre Y ou Y contre X. Doit être un `[u8]`.
- `amount` : le montant que l'utilisateur veut envoyer. Doit être un `[u64]`.
- `min` : le montant minimum que l'utilisateur accepte de recevoir. Doit être un `[u64]`.
- `expiration` : l'horodatage après lequel l'ordre est invalide. Doit être un `[i64]`.

Nous pouvons conserver la même structure :

```rust
pub struct SwapInstructionData {
    pub is_x: bool,
    pub amount: u64,
    pub min: u64,
    pub expiration: i64,
}

impl<'a> TryFrom<&'a [u8]> for SwapInstructionData {
    type Error = ProgramError;

    fn try_from(data: &'a [u8]) -> Result<Self, Self::Error> {
        //..
    }
}
```

> Vérifiez que `amount` et `min` sont strictement positifs, et rejetez les ordres expirés avec la sysvar `Clock`.

<ArticleSection name="Logique d'Instruction" id="instruction-logic" level="h2" />

Nous commençons par désérialiser `instruction_data` et `accounts`.

Nous devons ensuite :

- charger le compte `Config` avec `Config::load()`,
- vérifier que l'état de la pool est `AmmState::Initialized`,
- vérifier que `vault_x` et `vault_y` sont bien les comptes de jetons associés attendus,
- désérialiser les comptes de jetons des vaults et calculer le résultat du swap avec `constant-product-curve`.

Ce calcul reste identique :

```rust
let vault_x = unsafe { TokenAccount::from_account_info_unchecked(self.accounts.vault_x)? };
let vault_y = unsafe { TokenAccount::from_account_info_unchecked(self.accounts.vault_y)? };

let mut curve = ConstantProduct::init(
    vault_x.amount(),
    vault_y.amount(),
    vault_x.amount(),
    config.fee(),
    None,
)
.map_err(|_| ProgramError::Custom(1))?;

let p = match self.instruction_data.is_x {
    true => LiquidityPair::X,
    false => LiquidityPair::Y,
};

let swap_result = curve
    .swap(p, self.instruction_data.amount, self.instruction_data.min)
    .map_err(|_| ProgramError::Custom(1))?;

if swap_result.deposit == 0 || swap_result.withdraw == 0 {
    return Err(ProgramError::InvalidArgument);
}
```

Le changement important concerne l'etape de transfert. Tu as deja vu le pattern batch dans `deposit`, donc ajoute les deux transfers dans une `Batch` et invoque le token program une seule fois. Pour ce swap, la PDA `config` doit signer le transfert depuis le vault, donc utilise `batch.invoke_signed(&[signer])?;`.

Vous devez maintenant mettre à jour la logique finale de `process()` afin que :

- les validations et le calcul soient effectués d'abord,
- les deux instructions `Transfer` soient ajoutées à la batch,
- la batch soit invoquée une seule fois vers le token program à la fin.

La forme extérieure de l'instruction ne change pas :

```rust
pub struct Swap<'a> {
    pub accounts: SwapAccounts<'a>,
    pub instruction_data: SwapInstructionData,
}

impl<'a> TryFrom<(&'a [u8], &'a [AccountInfo])> for Swap<'a> {
    type Error = ProgramError;

    fn try_from((data, accounts): (&'a [u8], &'a [AccountInfo])) -> Result<Self, Self::Error> {
        let accounts = SwapAccounts::try_from(accounts)?;
        let instruction_data = SwapInstructionData::try_from(data)?;

        Ok(Self {
            accounts,
            instruction_data,
        })
    }
}

impl<'a> Swap<'a> {
    pub const DISCRIMINATOR: &'a u8 = &3;

    pub fn process(&mut self) -> ProgramResult {
        //..

        Ok(())
    }
}
```
