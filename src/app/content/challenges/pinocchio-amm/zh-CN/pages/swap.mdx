# 交换

`swap` 指令仍然执行同样的两个高层任务：

- 计算用户在扣除手续费后应当收到多少另一侧的代币。
- 将代币转入池子并从池子中转出。

<ArticleSection name="所需账户" id="required-accounts" level="h2" />

此上下文需要以下账户：

- `user`：执行 AMM 交换的用户。必须是 `signer`。
- `user_x_ata`：用户的 token X 关联代币账户。必须作为 `mutable` 传入。
- `user_y_ata`：用户的 token Y 关联代币账户。必须作为 `mutable` 传入。
- `vault_x`：池子持有 token X 的代币账户。必须作为 `mutable` 传入。
- `vault_y`：池子持有 token Y 的代币账户。必须作为 `mutable` 传入。
- `config`：AMM 配置账户。保存池子的状态和参数。
- `token_program`：代币程序账户。它用于执行转账和铸造等代币操作。必须是 `executable`。

账户解析逻辑保持不变：

```rust
pub struct SwapAccounts<'a> {

    pub user_x_ata: &'a AccountInfo,

    pub vault_y: &'a AccountInfo,
    pub config: &'a AccountInfo,

}

```

<ArticleSection name="指令数据" id="instruction-data" level="h2" />

指令数据同样保持不变：

- `is_x`：表示用户是从 X 换到 Y，还是从 Y 换到 X。必须是 `[u8]`。
- `amount`：用户愿意发送的数量。必须是 `[u64]`。
- `min`：用户愿意接收的最小数量。必须是 `[u64]`。
- `expiration`：订单失效的时间戳。必须是 `[i64]`。

我们可以保留相同的数据结构：

```rust
pub struct SwapInstructionData {
    pub is_x: bool,
    pub amount: u64,
    pub min: u64,
    pub expiration: i64,
}

impl<'a> TryFrom<&'a [u8]> for SwapInstructionData {
    type Error = ProgramError;

    fn try_from(data: &'a [u8]) -> Result<Self, Self::Error> {
        //..
    }
}
```

> 请确保 `amount` 和 `min` 都大于零，并使用 `Clock` sysvar 拒绝已经过期的订单。

<ArticleSection name="指令逻辑" id="instruction-logic" level="h2" />

我们首先要反序列化 `instruction_data` 和 `accounts`。

然后需要：

- 使用 `Config::load()` 加载 `Config` 账户，
- 验证池子的状态为 `AmmState::Initialized`，
- 验证 `vault_x` 和 `vault_y` 是预期的关联代币账户，
- 反序列化 vault 的代币账户，并使用 `constant-product-curve` 计算交换结果。

这部分计算仍然如下：

```rust
let vault_x = unsafe { TokenAccount::from_account_info_unchecked(self.accounts.vault_x)? };
let vault_y = unsafe { TokenAccount::from_account_info_unchecked(self.accounts.vault_y)? };

let mut curve = ConstantProduct::init(
    vault_x.amount(),
    vault_y.amount(),
    vault_x.amount(),
    config.fee(),
    None,
)
.map_err(|_| ProgramError::Custom(1))?;

let p = match self.instruction_data.is_x {
    true => LiquidityPair::X,
    false => LiquidityPair::Y,
};

let swap_result = curve
    .swap(p, self.instruction_data.amount, self.instruction_data.min)
    .map_err(|_| ProgramError::Custom(1))?;

if swap_result.deposit == 0 || swap_result.withdraw == 0 {
    return Err(ProgramError::InvalidArgument);
}
```

- 将代币转账批量合并到单一 CPI 中。你已经在 `deposit` 里见过 batch 的模式，所以这里我们对两条 `Transfer` 指令做同样的事情，只调用一次代币程序。由于从 vault 转出的那笔转账仍然需要 `config` PDA 签名，batch 应该以 `batch.invoke_signed(&[signer])?;` 结束。

```rust
const MAX_ACCOUNTS_LEN: usize = Transfer::MAX_ACCOUNTS_LEN * 2;
const MAX_DATA_LEN: usize = Batch::header_data_len(2) + Transfer::DATA_LEN * 2;

// ...

let mut batch_state = BatchState::new(MAX_ACCOUNTS_LEN, MAX_DATA_LEN);
let mut batch = batch_state.as_batch()?;

if self.instruction_data.is_x {
    Transfer::new(
        // ...
    )
    .into_batch(&mut batch)?;

    Transfer::new(
        // ...
    )
    .into_batch(&mut batch)?;
} else {
    Transfer::new(
        // ...
    )
    .into_batch(&mut batch)?;

    Transfer::new(
        // ...
    )
    .into_batch(&mut batch)?;
}

batch.invoke_signed(&[signer])?;
```

> 请确保 `pinocchio-token` 至少为 `0.6.0` 版本，以支持 [p-token](https://solana.com/upgrades/p-token) 的批量操作。

外层指令的结构保持不变：

```rust
pub struct Swap<'a> {
    pub accounts: SwapAccounts<'a>,
    pub instruction_data: SwapInstructionData,
}

impl<'a> TryFrom<(&'a [u8], &'a [AccountInfo])> for Swap<'a> {
    type Error = ProgramError;

    fn try_from((data, accounts): (&'a [u8], &'a [AccountInfo])) -> Result<Self, Self::Error> {
        let accounts = SwapAccounts::try_from(accounts)?;
        let instruction_data = SwapInstructionData::try_from(data)?;

        Ok(Self {
            accounts,
            instruction_data,
        })
    }
}
```
