# Swap

Die Instruction `swap` erfüllt weiterhin dieselben zwei Aufgaben auf hohem Niveau:

- Berechnen, wie viele Token der Gegenseite der Nutzer inklusive Gebühren erhalten soll.
- Token in den Pool hinein und aus dem Pool heraus bewegen.

<ArticleSection name="Benötigte Accounts" id="required-accounts" level="h2" />

Folgende Accounts werden in diesem Kontext benötigt:

- `user`: Der Nutzer, der im AMM swapt. Muss ein `signer` sein.
- `user_x_ata`: Das Associated Token Account des Nutzers für Token X. Muss als `mutable` übergeben werden.
- `user_y_ata`: Das Associated Token Account des Nutzers für Token Y. Muss als `mutable` übergeben werden.
- `vault_x`: Das Token Account, das Token X für den Pool hält. Muss als `mutable` übergeben werden.
- `vault_y`: Das Token Account, das Token Y für den Pool hält. Muss als `mutable` übergeben werden.
- `config`: Das Konfigurationskonto des AMM. Es speichert Pool-Zustand und Parameter.
- `token_program`: Das Token-Programm-Konto. Es wird für Token-Operationen wie Transfers und Minting benötigt. Muss `executable` sein.

Der Account-Parser bleibt unverändert:

```rust

```

<ArticleSection name="Instruction-Daten" id="instruction-data" level="h2" />

Auch die Instruction-Daten bleiben unverändert:

- `is_x`: Gibt an, ob der Nutzer X gegen Y oder Y gegen X tauscht. Muss ein `[u8]` sein.
- `amount`: Der Betrag, den der Nutzer senden will. Muss ein `[u64]` sein.
- `min`: Der Mindestbetrag, den der Nutzer erhalten will. Muss ein `[u64]` sein.
- `expiration`: Der Zeitstempel, nach dem die Order ungültig ist. Muss ein `[i64]` sein.

Wir können dieselbe Struktur beibehalten:

```rust
pub struct SwapInstructionData {
    pub is_x: bool,
    pub amount: u64,
    pub min: u64,
    pub expiration: i64,
}

impl<'a> TryFrom<&'a [u8]> for SwapInstructionData {
    type Error = ProgramError;

    fn try_from(data: &'a [u8]) -> Result<Self, Self::Error> {
        //..
    }
}
```

> Stelle sicher, dass `amount` und `min` beide größer als null sind, und lehne abgelaufene Orders über die `Clock`-Sysvar ab.

<ArticleSection name="Instruction-Logik" id="instruction-logic" level="h2" />

Wir beginnen damit, sowohl `instruction_data` als auch `accounts` zu deserialisieren.

Danach müssen wir:

- den `Config`-Account mit `Config::load()` laden,
- prüfen, dass der Pool-Zustand `AmmState::Initialized` ist,
- prüfen, dass `vault_x` und `vault_y` die erwarteten Associated Token Accounts sind,
- die Vault-Token-Accounts deserialisieren und das Swap-Ergebnis mit `constant-product-curve` berechnen.

Diese Berechnung bleibt gleich:

```rust
let vault_x = unsafe { TokenAccount::from_account_info_unchecked(self.accounts.vault_x)? };
let vault_y = unsafe { TokenAccount::from_account_info_unchecked(self.accounts.vault_y)? };

let mut curve = ConstantProduct::init(
    vault_x.amount(),
    vault_y.amount(),
    vault_x.amount(),
    config.fee(),
    None,
)
.map_err(|_| ProgramError::Custom(1))?;

let p = match self.instruction_data.is_x {
    true => LiquidityPair::X,
    false => LiquidityPair::Y,
};

let swap_result = curve
    .swap(p, self.instruction_data.amount, self.instruction_data.min)
    .map_err(|_| ProgramError::Custom(1))?;

if swap_result.deposit == 0 || swap_result.withdraw == 0 {
    return Err(ProgramError::InvalidArgument);
}
```

- Batch die Token-Transfers in einen einzigen CPI. Du hast das Batch-Pattern bereits in `deposit` gesehen, also machen wir hier dasselbe mit den beiden `Transfer`-Instruktionen und rufen das Token-Programm nur einmal auf. Da der Transfer aus dem Vault weiterhin die Signatur der `config` PDA benötigt, sollte der Batch mit `batch.invoke_signed(&[signer])?;` enden.

```rust
const MAX_ACCOUNTS_LEN: usize = Transfer::MAX_ACCOUNTS_LEN * 2;
const MAX_DATA_LEN: usize = Batch::header_data_len(2) + Transfer::DATA_LEN * 2;

// ...

let mut batch_state = BatchState::new(MAX_ACCOUNTS_LEN, MAX_DATA_LEN);
let mut batch = batch_state.as_batch()?;

if self.instruction_data.is_x {
    Transfer::new(
        // ...
    )
    .into_batch(&mut batch)?;

    Transfer::new(
        // ...
    )
    .into_batch(&mut batch)?;
} else {
    Transfer::new(
        // ...
    )
    .into_batch(&mut batch)?;

    Transfer::new(
        // ...
    )
    .into_batch(&mut batch)?;
}

batch.invoke_signed(&[signer])?;
```

> Stelle sicher, dass `pinocchio-token` mindestens Version `0.6.0` hat, um [p-token](https://solana.com/upgrades/p-token) Batch-Operationen zu unterstützen.

Die äußere Form der Instruction bleibt unverändert:

```rust
pub struct Swap<'a> {
    pub accounts: SwapAccounts<'a>,
    pub instruction_data: SwapInstructionData,
}

impl<'a> TryFrom<(&'a [u8], &'a [AccountInfo])> for Swap<'a> {
    type Error = ProgramError;

    fn try_from((data, accounts): (&'a [u8], &'a [AccountInfo])) -> Result<Self, Self::Error> {
        let accounts = SwapAccounts::try_from(accounts)?;
        let instruction_data = SwapInstructionData::try_from(data)?;

        Ok(Self {
            accounts,
            instruction_data,
        })
    }
}

impl<'a> Swap<'a> {

        Ok(())
    }
}
```
