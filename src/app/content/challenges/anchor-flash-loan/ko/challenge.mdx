# Anchor 플래시 론

![Anchor Flash Loan](/graphics/challenge-banners/anchor-flash-loan.png)

명령어 인트로스펙션은 블록체인 프로그램이 동일한 트랜잭션 번들 내의 다른 명령어를 검사하고 분석할 수 있게 해주는 강력한 기능입니다. 여기에는 아직 실행되지 않은 명령어도 포함되어, 프로그램이 "미리 보기"를 통해 트랜잭션에서 나중에 일어날 일을 기반으로 결정을 내릴 수 있습니다.

이는 트랜잭션에 대한 투시 능력을 갖는 것과 같습니다. 프로그램이 전체 트랜잭션을 꿰뚫어 보고 진행 방법을 결정하기 전에 전체 작업 순서를 이해할 수 있습니다.

명령어 인트로스펙션의 가장 매력적인 응용 사례는 플래시 론입니다. 이는 단일 트랜잭션의 경계 내에서만 존재하는 독특한 유형의 대출입니다.

플래시 론의 작동 방식은 다음과 같습니다:
- **대출**: 트랜잭션 시작 시 `loan` 명령어를 사용하여 즉시 대량의 자본을 빌릴 수 있습니다
- **사용**: 동일한 트랜잭션 내에서 이 빌린 자본을 거래, 차익거래 또는 기타 작업에 사용할 수 있습니다
- **상환**: 트랜잭션이 종료되기 전에 `repay` 명령어를 사용하여 대출금과 소액의 수수료를 상환해야 합니다

핵심은 플래시 론이 블록체인 트랜잭션의 원자성에 의존한다는 것입니다. 트랜잭션의 어느 부분이라도 실패하면(상환 포함), 전체 트랜잭션이 롤백되어 마치 발생하지 않은 것처럼 됩니다. 이는 대출자가 위험이 전혀 없다는 것을 의미합니다. 상환을 받거나, 대출이 실제로 발생하지 않거나 둘 중 하나입니다.

이 챌린지에서는 명령어 인트로스펙션을 실제로 보여주는 간단한 플래시 론 프로그램을 만들게 됩니다. 프로그램은 동일한 트랜잭션 내의 여러 명령어에 걸쳐 명령어 데이터와 계정을 검사하여 대출 조건이 충족되는지 확인합니다.

명령어 인트로스펙션이 처음이라면, 이 프로그램에서 사용되는 기본 개념을 이해하기 위해 [명령어 인트로스펙션 코스](/en/courses/instruction-introspection)부터 시작하는 것을 권장합니다.

<ArticleSection name="설치" id="installation" level="h2" />

시작하기 전에 Rust와 Anchor가 설치되어 있는지 확인하세요. 설치 방법이 필요하다면 [공식 Anchor 문서](https://www.anchor-lang.com/docs/installation)를 참조하세요. 그런 다음 터미널에서 다음을 실행하세요:

```bash
anchor init blueshift_anchor_flash_loan
```

필요한 의존성을 추가하세요:
- `anchor-spl`: SPL 토큰(솔라나의 토큰 표준) 작업을 위한 유틸리티를 제공합니다

```bash
cd blueshift_anchor_flash_loan
cargo add anchor-spl
```

이제 플래시 론 프로그램을 구축할 준비가 되었습니다!

<ArticleSection name="계정" id="accounts" level="h2" />

`borrow` 및 `repay` 명령어 모두 동일한 계정으로 작업하므로, 두 함수 모두에 사용되는 단일 `Loan` 컨텍스트를 만들 수 있습니다. 이렇게 하면 코드를 더 쉽게 유지 관리하고 이해할 수 있습니다.

`Loan` 계정 구조체에는 다음 구성 요소가 필요합니다:
- `borrower`: 플래시 론을 요청하는 사용자.
- `protocol`: 프로토콜의 유동성 풀을 소유하는 프로그램 파생 주소(PDA).
- `mint`: 차용되는 특정 토큰.
- `borrower_ata`: 차용한 토큰을 받을 차용자의 연결 토큰 계정.
- `protocol_ata`: 차용한 토큰을 제공할 프로토콜의 연결 토큰 계정.
- `instructions`: 인트로스펙션을 위한 Instructions Sysvar 계정.
- `token_program`, `associated_token_program` 및 `system_program`: 프로그램에 필요한 프로그램들.

계정 구조체를 다음과 같이 정의합니다:

```rust
#[derive(Accounts)]
pub struct Loan<'info> {
  #[account(mut)]
  pub borrower: Signer<'info>,
  #[account(
    seeds = [b"protocol".as_ref()],
    bump,
  )]
  pub protocol: SystemAccount<'info>,

  pub mint: Account<'info, Mint>,
  #[account(
    init_if_needed,
    payer = borrower,
    associated_token::mint = mint,
    associated_token::authority = borrower,
  )]
  pub borrower_ata: Account<'info, TokenAccount>,
  #[account(
    mut,
    associated_token::mint = mint,
    associated_token::authority = protocol,
  )]
  pub protocol_ata: Account<'info, TokenAccount>,

  #[account(address = INSTRUCTIONS_SYSVAR_ID)]
  /// CHECK: InstructionsSysvar account
  instructions: UncheckedAccount<'info>,
  pub token_program: Program<'info, Token>,
  pub associated_token_program: Program<'info, AssociatedToken>,
  pub system_program: Program<'info, System>
}
```

보시다시피, 이 명령어에 필요한 계정과 제약 조건은 매우 간단합니다:
- `protocol`: `seeds = [b"protocol".as_ref()]`를 사용하여 모든 프로토콜 유동성을 소유하는 결정론적 주소를 생성합니다. 이를 통해 우리 프로그램만 이러한 자금을 제어할 수 있습니다.
- `borrower_ata`: `init_if_needed`를 사용합니다. 차용자가 이 특정 토큰에 대한 연결된 토큰 계정을 아직 가지고 있지 않을 수 있기 때문입니다. 이 제약 조건은 필요한 경우 자동으로 계정을 생성합니다.
- `protocol_ata`: 토큰을 전송할 것이므로 이미 존재하고 변경 가능해야 합니다. `associated_token::authority = protocol` 제약 조건은 프로토콜 PDA만 전송을 승인할 수 있도록 보장합니다.
- `instructions`: `address` 제약 조건을 사용하여 트랜잭션 명령어 데이터가 포함된 올바른 시스템 계정에 액세스하고 있는지 확인합니다.

<ArticleSection name="오류" id="errors" level="h2" />

플래시 론은 여러 단계에서 정확한 검증이 필요하므로 포괄적인 오류 처리가 필요합니다. 다음은 완전한 오류 열거형입니다:

```rust
#[error_code]
pub enum ProtocolError {
    #[msg("Invalid instruction")]
    InvalidIx,
    #[msg("Invalid instruction index")]
    InvalidInstructionIndex,
    #[msg("Invalid amount")]
    InvalidAmount,
    #[msg("Not enough funds")]
    NotEnoughFunds,
    #[msg("Program Mismatch")]
    ProgramMismatch,
    #[msg("Invalid program")]
    InvalidProgram,
    #[msg("Invalid borrower ATA")]
    InvalidBorrowerAta,
    #[msg("Invalid protocol ATA")]
    InvalidProtocolAta,
    #[msg("Missing repay instruction")]
    MissingRepayIx,
    #[msg("Missing borrow instruction")]
    MissingBorrowIx,
    #[msg("Overflow")]
    Overflow,
}
```

이러한 기반이 마련되면 플래시 론 명령어의 핵심 로직을 구현할 준비가 완료됩니다. 계정 구조는 적절한 토큰 처리를 보장하고, 오류 시스템은 디버깅 및 보안 검증을 위한 명확한 피드백을 제공합니다.
