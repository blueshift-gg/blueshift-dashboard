<ChallengeTitle>sBPF Assembly Slippage</ChallengeTitle>

Agora que você está começando a se sentir confortável escrevendo Assembly, em vez de usar apenas uma conta normal, sua verificação de slippage deve funcionar tanto para contas SPL-Token quanto Token2022.

> O `amount` será colocado na memória na mesma constante do exemplo. A principal diferença é que não podemos obter os dados da instrução usando uma constante, já que o `data_len` da conta é dinâmico (os dados da instrução estão localizados no final dos dados da última conta).

Crie um programa que tenha apenas uma instrução. Ela deve:
- Receber uma única conta SPL ou Token2022 Token
- Receber um u64 (8 bytes) de saldo mínimo nos dados da instrução
- Calcular dinamicamente o offset para o saldo mínimo
- Se o slippage for excedido, registrar a string `Slippage exceeded` e retornar o código de erro 1

> Para obter o offset correto dos dados da instrução, você pode usar nossa [ferramenta](https://sbpf.xyz). Mas vamos te ajudar: o `data_len` da conta token está em `.equ TOKEN_ACCOUNT_DATA_LEN, 0x0058`

Comece instalando o pacote sBPF como explicado na [seção de ferramentas](/pt-BR/courses/introduction-to-assembly/tooling) do curso de Introdução ao Assembly e compile seu programa usando o seguinte comando no seu terminal:

```
sbpf build
```

Isso gerará um arquivo `.so` na sua pasta `target/deploy`.

Agora clique no botão `take challenge` e solte o arquivo lá!

  <Requirement title="Desafio 1: Testando o Slippage com SPL-Token">

  <Requirement title="Desafio 3: Testando o Slippage com Token2022">

</RequirementList>
