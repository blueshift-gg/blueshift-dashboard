# 피노키오 플래시 론

![Pinocchio Flash Loan](/graphics/challenge-banners/pinocchio-flash-loan.png)

명령어 인트로스펙션은 블록체인 프로그램이 동일한 트랜잭션 번들 내의 다른 명령어를 검사하고 분석할 수 있게 해주는 강력한 기능입니다. 여기에는 아직 실행되지 않은 명령어도 포함되어, 프로그램이 트랜잭션에서 나중에 발생할 일을 "미리 보고" 그에 따라 결정을 내릴 수 있습니다.

이는 트랜잭션에 대한 투시 능력을 갖는 것과 같습니다. 프로그램이 전체 트랜잭션을 꿰뚫어 보고 진행 방법을 결정하기 전에 전체 작업 순서를 이해할 수 있습니다.

명령어 인트로스펙션의 가장 매력적인 응용 사례는 플래시 론입니다. 이는 단일 트랜잭션의 경계 내에서만 존재하는 독특한 유형의 대출입니다.

플래시 론의 작동 방식은 다음과 같습니다:
- **대출**: 트랜잭션 시작 시 `loan` 명령어를 사용하여 즉시 대량의 자본을 빌릴 수 있습니다
- **사용**: 동일한 트랜잭션 내에서 이 빌린 자본을 거래, 차익거래 또는 기타 작업에 사용할 수 있습니다
- **상환**: 트랜잭션이 종료되기 전에 `repay` 명령어를 사용하여 대출금과 소액의 수수료를 상환해야 합니다

핵심은 플래시 론이 블록체인 트랜잭션의 원자성에 의존한다는 것입니다. 트랜잭션의 어느 부분이라도 실패하면(상환 포함), 전체 트랜잭션이 롤백되어 마치 발생하지 않은 것처럼 됩니다. 이는 대출자가 위험이 전혀 없다는 것을 의미합니다. 상환을 받거나, 대출이 실제로 발생하지 않거나 둘 중 하나입니다.

이 챌린지에서는 명령어 인트로스펙션을 실제로 보여주는 간단한 플래시 론 프로그램을 만들게 됩니다. 프로그램은 동일한 트랜잭션 내의 여러 명령어에 걸쳐 명령어 데이터와 계정을 검사하여 대출 조건이 충족되는지 확인합니다.

instruction introspection을 처음 접하는 경우, 이 프로그램에서 사용되는 기본 개념을 이해하기 위해 [Instruction Introspection 과정](/en/courses/instruction-introspection)부터 시작하는 것을 권장합니다.

<ArticleSection name="설치" id="installation" level="h2" />

시작하기 전에 Rust와 Pinocchio가 설치되어 있는지 확인하세요. 그런 다음 터미널에서 다음을 실행하세요:

```bash
# create workspace
cargo new blueshift_pinocchio_flash_loan --lib --edition 2021
cd blueshift_pinocchio_flash_loan
```

`pinocchio`, `pinocchio-system`, `pinocchio-token`를 추가하세요:

```bash
cargo add pinocchio pinocchio-system pinocchio-token
```

`Cargo.toml`에서 crate 타입을 선언하여 `target/deploy`에 배포 아티팩트를 생성하세요:

```toml
[lib]
crate-type = ["lib", "cdylib"]
```

이제 플래시 론 프로그램을 작성할 준비가 되었습니다.

<ArticleSection name="템플릿" id="template" level="h2" />

이번에는 모든 것을 `lib.rs`에 배치하는 대신 프로그램을 작고 집중된 모듈로 분할하겠습니다. 폴더 트리는 대략 다음과 같습니다:

```
src
├── instructions
│       ├── helpers.rs
│       ├── loan.rs
│       ├── mod.rs
│       └── repay.rs
├── lib.rs
```

**참고**: 프로그램을 테스트하기 위해 내부적으로 이것을 사용하므로 프로그램 ID를 `22222222222222222222222222222222222222222222`로 변경하는 것을 잊지 마세요.

`lib.rs`의 엔트리포인트는 [Pinocchio 소개 과정](/en/courses/introduction-to-pinocchio)에서 다룬 내용과 매우 유사합니다.

```rust
use pinocchio::{account_info::AccountInfo, entrypoint, program_error::ProgramError, pubkey::Pubkey, ProgramResult};
entrypoint!(process_instruction);

pub mod instructions;
pub use instructions::*;

// 22222222222222222222222222222222222222222222
pub const ID: Pubkey = [
    0x0f, 0x1e, 0x6b, 0x14, 0x21, 0xc0, 0x4a, 0x07, 
    0x04, 0x31, 0x26, 0x5c, 0x19, 0xc5, 0xbb, 0xee, 
    0x19, 0x92, 0xba, 0xe8, 0xaf, 0xd1, 0xcd, 0x07, 
    0x8e, 0xf8, 0xaf, 0x70, 0x47, 0xdc, 0x11, 0xf7, 
];

fn process_instruction(
    _program_id: &Pubkey,
    accounts: &[AccountInfo],
    instruction_data: &[u8],
) -> ProgramResult {
    match instruction_data.split_first() {
        Some((Loan::DISCRIMINATOR, data)) => Loan::try_from((data, accounts))?.process(),
        Some((Repay::DISCRIMINATOR, _)) => Repay::try_from(accounts)?.process(),
        _ => Err(ProgramError::InvalidInstructionData)
    }
}
```

<ArticleSection name="헬퍼" id="helpers" level="h2" />

`loan` 및 `repay` 명령어를 살펴보기 전에 `helpers.rs`를 먼저 살펴보겠습니다:

```rust
#[repr(C, packed)]
pub struct LoanData {
    pub protocol_token_account: [u8; 32],
    pub balance: u64,
}

pub fn get_token_amount(data: &[u8]) ->  Result<u64, ProgramError> {
    if !account.is_owned_by(&pinocchio_token::ID) {
        return Err(PinocchioError::InvalidOwner.into());
    }

    if account.data_len().ne(&pinocchio_token::state::TokenAccount::LEN) {
        return Err(PinocchioError::InvalidAccountData.into());
    }

    Ok(u64::from_le_bytes(data[64..72].try_into().unwrap()))
}
```

이 파일은 간단합니다. 대출이 상환되기 전에 계정에 대출 데이터를 임시로 저장하는 데 사용할 `LoanData` 구조체가 포함되어 있습니다. 또한 계정에서 토큰 금액을 읽는 `get_token_amount()` 헬퍼 함수를 제공합니다.
